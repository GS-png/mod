# EW-119 性能与压力测试记录

## 记录目的
- 这份记录对应 `EW-119`。
- 它专门盯四种会一起把机器和逻辑压满的东西：多魔王、持续出波、区域技能、HUD 同开。
- 目标不是追漂亮数字，而是先排查有没有明显卡死、爆日志或界面刷坏。

## 当前证据
- `Observed`：多魔王场景已经有 `联盟 / 内战 / 随机` 三种关系模式，随机模式还会按间隔重掷。
- `Observed`：军团系统默认每 `10年` 出波，第一波 `40` 支，同时上限 `300`，后续按 `15%/波` 递增。
- `Observed`：HUD 已支持显示开关、样式切换、拖拽和位置记忆，并持续显示轮回、阶段、封印和态势摘要。
- `Observed`：当前仓库至少能通过一次源码级编译冒烟，见 [EW-008_空模组加载冒烟记录.md](EW-008_空模组加载冒烟记录.md)。
- `Unknown`：仓库里没有真实实机环境，所以这份文档先给压力脚本，还没有实测性能结果。

## 压测前准备
1. 先完成 [EW-114_启动自检清单.md](EW-114_启动自检清单.md) 的启动检查。
2. 参数建议这样配：启用魔王至少 `3` 名，`苏醒数量 >= 3`，互动模式优先测 `随机`。
3. HUD 保持开启。先用标准样式跑一轮，再切到紧凑样式跑一轮。
4. 全程记录 `[事件]`、`[战斗]`、`[调试]`、`[校验]` 几类日志，像看仪表灯一样盯异常峰值。

## 基础压力脚本
1. 用调试窗口把轮回直接推进到 `降临`。
2. 观察至少 `3` 名魔王同时在场，且已经出过至少 `2` 波军团。
3. 保持相机在主战场附近，连续观察 `5-10` 分钟。
4. 期间不要关 HUD。确认 HUD 数字会持续刷新，但不会闪烁、错位或卡住不动。

## 进阶压力脚本
1. 把互动模式切到 `随机`。这样多魔王关系会在联盟和内战之间反复重算。
2. 让场上保留多个区域技能效果。重点看持续范围类、召唤类和牵引类效果叠在一起时的表现。
3. 再把 HUD 从标准样式切到紧凑样式，并拖拽一次位置。确认压测中途切样式不会把 HUD 弄丢。
4. 如果机器还能顶住，就继续观察到下一次军团出波，确认新旧波次叠加时没有明显停顿。

## 重点观察项
- 画面是否出现持续 `3-5` 秒以上的明显卡死。
- 日志是否短时间刷出同一条异常，像瀑布一样滚屏。
- HUD 是否还能正确显示轮回数、阶段、多魔王关系和军团态势。
- 关系重掷、军团出波和区域技能叠加时，游戏是否还能继续推进。

## 通过标准
- 不出现明显卡死。
- 不出现持续爆日志或同类异常刷屏。
- HUD 在高压场景下仍可见、可读、可切样式。
- 多魔王关系、军团波次和阶段推进不会在压力下失步。

## 当前边界
- `Observed`：设计参数已经把多魔王、军团数量和成长区间写成了明确口径。
- `Unknown`：真实帧率、内存峰值和不同机器差异，当前仓库还没有自动采样工具，需要实机继续补数据。
