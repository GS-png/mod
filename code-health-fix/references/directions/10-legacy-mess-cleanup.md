# 10. 屎山代码清理

## 这个方向要解决什么

找“历史包袱把当前改动卡住”的地方。
屎山代码像旧房子里乱接的电线，不一定马上炸，但每次想修一盏灯，都得先绕开一堆旧线头。

## 什么时候把它列为不同评级

- `必须`：用户明确说“拆屎山”，或当前目标文件里有大量历史兜底、废弃分支、深层嵌套
- `建议`：老模块难读难改，历史兼容逻辑明显偏多
- `可选`：有少量旧痕迹，但不影响本轮主目标
- `不必`：当前范围是新代码或边界很清晰，没有明显历史包袱

## 检查边界

- 只清理阻碍当前工作的历史包袱
- 不借机发起全仓大扫除
- 如果删除旧逻辑会影响未知外部方，先找证据再下手

## 先收集这些证据

- 注释掉的大块代码、废弃分支、兼容兜底
- 深层嵌套、魔法数字、模糊命名
- “先这样顶着”的历史注释、TODO、HACK
- 相关调用点和测试

## 分步检查

1. 标出真正阻碍当前维护的旧块
2. 判断哪些代码已经死掉，哪些只是没人敢删
3. 把魔法数字、分支开关、兜底链的来源查清
4. 先删能证明无用的旧代码，再收口剩余分支
5. 如果暂时删不掉，明确标记成过渡代码和阻塞原因

## 修复要求

- 优先删死代码、废弃分支、注释旧块
- 把历史兜底压缩成更清楚的规则，不要再叠一层新兜底
- 修改后补最小相关验证，防止误删活路径

## 完成标志

- 阻碍当前工作的历史包袱减少了
- 旧逻辑、废弃分支或注释旧代码真实删除了一部分
- 剩余没拆掉的过渡代码有明确说明

## 不要做

- 不要把“看着不爽”当删除理由
- 不要删不清楚来源的兼容逻辑却不做验证
- 不要在旧逻辑上继续叠新的兜底分支
