## 术语速查（必读）

| 术语 | 含义 |
|---|---|
| 轮回（Cycle） | 从"魔王被再封印"到"下一次魔王被再封印"的完整周期 |
| 阶段（Stage） | 轮回内的进程阶段（预发展/预兆/苏醒/降临/封印战（衰弱期）/重建） |
| 战斗子状态 | 仅在"降临"阶段生效，用于描述魔王强弱变化（全盛/常态），不改变轮回阶段 |

| 将领封印/魔王封印 | 双封印机制：将领封印在预兆阶段衰减（→苏醒）；魔王封印在苏醒阶段衰减（→降临） |
| 三钩子 | 技能触发的三种钩子：命中（`action_attack_target`）、受击（`action_get_hit`）、死亡点（`action_on_object_remove`） |

| 纪元遗产（Legacy） | 轮回结算后给予王国/英雄/魔王的永久增益（跨轮回继承） |
| P0 / S1-S6 | 技能标记口径：P0=被动；S1-S6=主动技能（按序号区分） |

## 第一部分：项目概述

### 1.1 核心理念

**一句话概括**：将 WorldBox 变成一个"自我讲述的史诗叙事引擎"，通过 AI 驱动的动态轮回系统，让每场游戏都是独一无二的王国兴衰史。

### 1.2 玩法闭环（游戏循环 + 系统关系）
<a id="s12"></a>

**游戏循环流程**：轮回从预发展开始，经历预兆/苏醒/降临/封印战，最终结算并进入下一轮。

#### 1.2.1 系统关系总览（开发视角）

**系统关系（从驱动到结果）**
- 轮回系统驱动阶段推进 → 魔王状态机切换 → 军团波次与将领激活
- 王国与英雄形成抗魔等级与遗产 → 提升对抗能力
- 轮回结算 → 纪元遗产 → 影响下一轮回

| 系统 | 主要作用 | 关键输入 | 关键输出 |
|---|---|---|---|
| 轮回系统 | 驱动阶段与结算 | 繁荣度/将领封印/魔王封印/轮回数 | 当前阶段/结算结果 |
| 魔王状态机 | 决定魔王行为与技能 | 当前阶段/HP/魔王类型 | 技能激活/强度与行为 |
| 纪元遗产 | 轮回的“记忆” | 轮回结算数据 | 王国/魔王遗产 |
| 军团波次 | 敌军生成节奏 | 阶段/波次配置/军团库 | 军团生成与规模 |
| 王国与英雄 | 反哺与对抗系统 | 王国/英雄运行态 | 抗魔等级/英雄晋升 |
| 将领系统 | 精英单位与指挥层 | 魔王类型/轮回数 | 将领激活与技能 |
| 军团系统 | 单位库与规格 | 魔王类型/军团配置 | 军团单位与生成规则 |


### 1.3 核心特色

| 特色 | 说明 |
|------|------|
| **轮回系统** | 每次"被再封印"为一个完整轮回；双方都变强；故事有记忆 |
| **十大魔王** | 机制完全不同，完整列表在 [魔王名册与技能表](魔王名册与技能表.md#appendix-demon-skills) |
| **多魔王互动** | 当 2+ 魔王同时苏醒，可切换联盟/内战/随机等模式，世界局势明显变化 |
| **纪元遗产** | 轮回结算后王国+英雄+魔王获得遗产：王国侧以“工艺/研究”解锁装备与能力，魔王侧以“征服/魔能”强化军势（均可配置） |
| **英雄系统** | 命定英雄由系统“晋升产生”（每王国/每轮回有上限）；以属性/特性/事件塑造故事主角，不依赖接管底层 AI 行为树 |
| **后备事件池** | 200+事件，无LLM也能运行；有LLM则故事更丰富 |
| **完整可控性** | 玩家对 MOD 关键参数与运行状态有控制权；参数可改、可导出、可调试（对游戏底层状态不做“全量可控”承诺） |

### 1.4 成功指标

**说明**：本节是高层目标摘要；详细验收与回归清单在版本规划章节统一列出。

| 指标 | 目标 |
|------|------|
| **完整轮回** | 同一存档完成至少 5 次完整轮回，计数正确，无崩溃 |
| **故事感** | 即使不配 LLM，也有 200+ 事件产生丰富叙事 |
| **可玩性** | 高轮回（5+）仍有解法，不会无解死档 |
| **易用性** | 关键参数可调；设置分新手/高级 |
| **鲁棒性** | 配置错误自动回退默认，游戏不崩溃，有错误提示 |

## 第二部分：核心系统规则

本部分按系统优先级讲解。各系统按 **概念 → 触发 → 持续 → 表现 → 结束 → 参数表** 的顺序组织；不适用的项会明确说明。

### 2.1 轮回系统（核心驱动）
<a id="s21"></a>

轮回系统负责阶段推进与结算，阶段顺序见「2.1.2 轮回阶段详解」。  


#### 2.1.1 核心概念

- **轮回计数** 从 0 开始，每次被再封印时 +1
- **轮回数据** 写入游戏存档或 MOD 自有存档文件，与游戏存档/读档联动，不需要额外存档按钮
- **轮回历史** 记录轮回时间线与对比数据

#### 2.1.2 轮回阶段详解

##### [1] 预发展阶段

**触发条件**：
- 游戏开始时自动进入
- 每次“战后重建”结束后自动进入（新一轮开始）

**持续规则**：
- MOD 监控王国发展，按“预发展_检查间隔”定期检查阈值

**状态表现**：
- 魔王处于封印状态，将领封印/魔王封印为初始强度
- 周围逐渐生成魔气节点（可视化）

**结束条件**：
- 世界达到"繁荣度"阈值（**世界现存人口阈值**或**世界现存城市阈值**满足其一） → 进入预兆阶段

##### [2] 预兆阶段

**触发条件**：
- 世界达到繁荣度阈值 → 自动进入

**持续规则**：
- 魔王势力的生成地点在地图上确定并显示
- 预兆阶段开始时立即生成第1波军团，之后按"军团_生成间隔"周期生成
- **将领封印**开始衰减（速率可配置）

**状态表现**：
- 地图上出现魔王据点标记
- 军团波次开始活动
- 将领封印进度条显示

**结束条件**：
- 将领封印衰减至 0% → 进入苏醒阶段

##### [3] 苏醒阶段

**触发条件**：
- 将领封印 = 0%（将领苏醒）

**持续规则**：
- 5 名将领一次性生成
- 军团继续按波次生成
- **魔王封印**开始衰减（速率可配置）

**状态表现**：
- 将领头像/标记可见
- 魔王封印进度条显示
- 战斗事件增多

**结束条件**：
- 魔王封印衰减至 0% → 进入降临阶段

##### [4] 降临阶段（全盛入侵）

**触发条件**：
- 魔王封印 = 0%（魔王苏醒）

**持续规则**：
- 魔王实体在地图上生成（全盛状态），使用自定义模板生成
- 军团继续按波次生成
- 魔王主动发起进攻

**状态表现**：
- 魔王头像/标记可见
- 根据魔王类型改变地形视觉

**结束条件**：
- 魔王生命值低于衰弱阈值 → 进入封印战（衰弱期）

##### [5] 封印战阶段（衰弱期）

**触发条件**：
- 魔王 HP 低于衰弱阈值

**持续规则**：
- 魔王优先逃离战场，修复/恢复
- 军团生成按“封印战波次速度倍率”降速
- 部分将领可能撤退/失控（离场或脱离据点防线）
- 英雄乘机追击
- 系统自动生成封印遗迹（自定义建筑）与“仪式区域”（范围检测 + 进度条逻辑）；遗迹数量可配置
- **胜利模式**（可配置，任一达成即胜）：
  1. **击杀封印**：直接击杀魔王
  2. **仪式封印**：友方单位在遗迹范围内完成“占据”（先清理完遗迹范围内的魔王势力，且人数达到阈值）即可**触发占领状态**；触发后进度持续推进，不要求继续驻守，除非触发中断条件。
     - 任意遗迹进入“已占领”后，该遗迹的**仪式进度条立即开始推进**并累积至 100%；不会因人数离开而暂停。
     - **中断判定**：遗迹范围内再次出现魔王势力且人数达到阈值时，判定为被打断（阈值可配置）。
     - **封印判定**：已占领遗迹数量 ≥ 封印阈值，且这些已占领遗迹的进度条达到 100% 时，魔王被封印。
     - 参数：占领人数/清场要求/占领遗迹数量/进度速度/中断条件可配置
  3. **双通道**：击杀封印与仪式封印任一达成即胜

**状态表现**：
- 魔王标记显示"虚弱"状态
- 封印遗迹标记在地图上
- 封印进度与胜利方式提示（按当前模式显示）

**结束条件**：
- 满足任意胜利条件 → 魔王被再封印（胜利条件可配置）
- 或魔王恢复到“封印战_回退_HP阈值”以上 → 回到降临阶段

##### [6] 战后重建阶段

**触发条件**：
- 魔王被再封印

**持续规则**：
- **轮回结算**：计算本轮数据、统计伤害、评估胜利程度
- **遗产发放**：王国获得纪元遗产
- **魔王处理**：
  - 重置位置到世界某处
  - 强度根据轮回成长倍率提升
  - 据点清除或净化
- **转移状态**：进入预发展阶段
- **轮回计数** +1

**结果呈现**：
- 弹窗显示"轮回总结"
  - 本轮轮回次数、耗时、伤亡数据
  - 获得的遗产列表
  - 下轮对手强度预估

#### 2.1.3 保护机制

- **封印胜利保底**：可配置是否启用“击杀封印”保底规则

#### 2.1.4 实现要点（开发）

- 轮回数据写入游戏存档或 MOD 存档，读档自动恢复。
- 封印遗迹使用自定义 `BuildingAsset`，不是改造原建筑。
- 封印战阶段生成遗迹，魔王被再封印后统一移除，下一轮回重新随机生成。
- 生成点避开深水与拥挤区域，遗迹之间保持最小间距。
- 点位不足时允许小范围生成地点修正。
- 仪式占领与进度条由 MOD 逻辑驱动，不依赖原版占领。

#### 2.1.5 参数表（可调）

**轮回与阶段**

| 参数组 | 可调控（UI） | 说明 | 使用章节 |
|------|-----|------|------|
| 预兆触发 | `世界现存人口阈值`：数值（5000人口）；`世界现存城市阈值`：数值（20城市）；`预发展_检查间隔`：数值（10年） | 人口/城市任一达标进入预兆 | 2.1 |
| 将领封印 | `将领封印_初始强度`：数值（100%）；`将领封印_衰减速率`：数值（1%/年） | 预兆阶段开始衰减 | 2.1 |
| 魔王封印 | `魔王封印_初始强度`：数值（100%）；`魔王封印_衰减速率`：数值（1%/年） | 苏醒阶段开始衰减 | 2.1 |

**封印遗迹与仪式封印**

### 2.2 魔王系统
<a id="s22"></a>

魔王系统区分“阶段状态 + 战斗子状态”，由轮回阶段与 HP 阈值驱动切换。

#### 2.2.1 核心概念

为避免“阶段”和“战斗态”混淆，魔王状态机分两层：
- **阶段状态（与 2.1 轮回阶段一一对应）**：预发展（封印） → 预兆 → 苏醒 → 降临 → 封印战（衰弱期） → 战后重建  
- **战斗子状态（仅在“降临”阶段生效）**：全盛 / 常态  

阶段状态决定是否有实体、军团与封印战；战斗子状态只影响强度、技能频率与波次速度。
支持魔王池勾选与苏醒模式配置。

#### 2.2.2 状态转换图（对齐 2.1）

本节用于说明状态切换与行为差异，阶段触发规则已在轮回阶段详解中给出。

#### 2.2.3 状态行为对照表（主状态）

| 主状态（阶段） | 技能激活 | 军团生成 | 将领数量 | 魔王 | 说明 |
|------|---------|--------|--------|--------|--------|
| 预发展/封印 | ❌ | ❌ | 0 | ❌ | 无实体，等待繁荣度触发 |
| 预兆 | ❌ | ✅ | 0 | ❌ | 军团开始生成，将领封印衰减 |
| 苏醒 | 将领技能 | ✅ | 固定5名 | ❌ | 将领生成，魔王封印衰减 |
| 降临 | 全部可用 | ✅ | 存活数 | ✅全盛 | 魔王生成（全盛），正式入侵 |
| 封印战（衰弱期） | 被动为主 | ✅（降速） | 存活数 | ✅虚弱 | 围绕遗迹与仪式推进 |
| 战后重建 | ❌ | ❌ | 0 | ❌ | 轮回结算与重置 |

**战斗子状态（仅在“降临”阶段）**：
- **全盛**：HP 高于全盛阈值时进入全盛；法力恢复 +50%，波次速度 ×2
- **常态**：HP 介于衰弱阈值与全盛阈值之间的默认状态，无额外加成
- **转换规则**：HP 下降至全盛阈值以下 → 进入常态；HP 回升至全盛阈值以上 → 回到全盛

#### 2.2.4 魔王成长

**魔王成长公式**：
```
属性值 = 基础值 × (1 + 轮回成长倍率 × 轮回数)
```

**适用范围**：
- 魔王本体基础属性（伤害/生命/防御/法力等基础值）

**基础值来源**：生成时按「[2.7 主角单位属性随机范围](#s27)」写入的随机基础值。  
**生效时机**：每次轮回结算后，对下一轮回生效。  
**成长特点**：线性增长，便于预估强度。

#### 2.2.5 魔王名册与技能表

名册与技能表： [魔王名册与技能表](魔王名册与技能表.md#appendix-demon-skills)。

#### 2.2.6 多魔王互动模式（联盟/内战/随机）
<a id="s225"></a>

> 目标：当同一轮回里出现 2 个及以上魔王时，明确“魔王之间”的关系规则，并在表现层呈现“内战”或“联合对抗世界”的大事件。

**触发条件（任一满足）**：
- 本轮苏醒数量 ≥ 2
- 当前存活魔王数量 ≥ 2

**模式（可切换/可配置）**：
- **魔王联盟**（`alliance`）：强制结盟、共享敌对关系、相互支援；统一把所有非魔王阵营当敌人。**为防难度爆炸，联盟模式下单体强度会下调**。
- **魔王内战**（`civilwar`）：魔王互相宣战，同时也攻击所有非魔王阵营（三方混战）。
- **随机判断**（`random`）：按权重随机决定关系。

**魔王联盟规则**：
- 魔王之间的战争必须被立即终止，并阻止再次开战。
- 每个魔王阵营都与所有王国阵营保持战争关系。
- 为避免难度爆炸，**联盟模式下单个魔王强度小幅下调**。

**魔王内战规则**：
- 魔王阵营两两宣战，同时对王国宣战。
- 参与魔王上限可配置，超过则随机抽取对战组合。
- **主导权机制**：击败其他魔王后，胜者获得被击败魔王的属性加成（按比例）与称号，持续时长可配置。

**保护机制**：
- 魔王数量 < 2 时，本模式不生效。
- 任一魔王被再封印/死亡后，立即更新关系与联盟。

**实现要点（开发）**：
- 每个魔王使用独立 `Kingdom` 作为阵营载体。
- 宣战/停战通过 `World.world.wars.newWar/endWar`。
- 防重复使用 `DiplomacyHelpers.isThereFightBetween`。
- 联盟关系用 `AllianceManager.forceAlliance/newAlliance`。
- 关系维护按间隔校验并修正，避免 AI 自发改变。

### 2.3 纪元遗产系统（轮回的"记忆"）
<a id="s23"></a>

纪元遗产在轮回结算时发放，跨轮回继承，体现「记忆」与长期成长。

#### 2.3.1 核心概念

每次轮回结算后，**王国、英雄、魔王都会获得各自的「纪元遗产」**。
王国遗产影响王国与英雄；魔王遗产影响魔王阵营。
遗产用于「机制解锁/方向强化」；魔王成长用于「基础数值抬升」。

#### 2.3.2 遗产分类与机制

**核心规则**：
- **世界档位**：全世界共享档位，按轮回结算推进（上限可配置）
- **机制解锁**：解锁类遗产（工艺/研究/军备）的解锁池对全世界生效
- **王国生效档位**：存活王国直接使用世界档位；新建王国按"掌握度"折算生效档位

| 遗产类型 | 效果（规则） | 档位规则 |
|---------|---------|--------|
| **工艺遗产（王国）** | 解锁更高阶装备/材料池；按原版装备制作/领取逻辑**概率获得**（全王国可用，英雄/精英权重更高，非全体必得） | 随档位扩展装备池（上限可配置） |
| **研究遗产（王国）** | 解锁"研究技能池"能力；按原版"特质/成长"逻辑**概率获得**（全王国可用，英雄/精英权重更高，非全体必得） | 随档位扩展技能池（上限可配置） |
| **军事遗产（王国）** | 提升对魔王阵营单位的攻击与防御 | 加成幅度随档位递增（可配置） |
| **传承遗产（英雄）** | 提升英雄后代晋升评分与英雄基础属性 | 加成幅度随档位递增（可配置） |

**魔王遗产（魔王阵营）**：

| 遗产类型 | 效果（规则） | 档位规则 |
|---------|---------|--------|
| **征服遗产（魔王）** | 提升魔王阵营基础伤害与防御 | 加成幅度随档位递增（可配置） |
| **军备遗产（魔王）** | 解锁魔王专属装备池；生成/补给时**按概率配装**（魔王/将领权重更高，非全体必得） | 随档位扩展装备池（上限可配置） |
| **魔能遗产（魔王）** | 提升魔王/将领法力上限与回复 | 加成幅度随档位递增（可配置） |
| **领域遗产（魔王）** | 提升领域类技能半径/次数（只影响 MOD 技能） | 加成幅度随档位递增（可配置） |

**口径说明**：战斗数值强化主要归魔王遗产；王国侧以“工艺解锁/装备强化/英雄传承”为主，避免变成“王国也直接数值碾压”的不合理体验。  
**档位规则说明**：
- 档位随轮回结算推进，上限可配置。
- **解锁类（工艺/研究/军备）**：档位只扩展可用清单，不直接叠加数值。
- **数值类（军事/传承/征服/魔能/领域）**：收益递增（档位越高增量越大，可配置）。

**生效规则**：
- 遗产不是“全员立刻强化”，而是“解锁池 + 被动加成”，通过原版获取/成长流程逐步出现。
- 解锁类（工艺/研究/军备）随制作/领取/补给流程概率获得，英雄/精英权重更高。
- 数值类（军事/传承/征服/魔能/领域）为被动加成，随档位递增。

#### 2.3.3 解锁规则摘要

> 详细装备/技能清单见「[遗产档位详表](遗产档位详表.md#legacy-items)」，下表为规则摘要。

| 遗产类型 | 档位范围（可配置） | 每档解锁内容 |
|---------|---------|-------------|
| 工艺遗产（王国） | 随档位解锁 | 装备数量与清单见遗产档位详表 |
| 研究遗产（王国） | 随档位解锁 | 技能数量与清单见遗产档位详表 |
| 军备遗产（魔王） | 随档位解锁 | 装备数量与清单见遗产档位详表 |

完整清单见「[遗产档位详表](遗产档位详表.md#legacy-items)」。


#### 2.3.4 王国掌握度与继承规则

**核心思路**：  
- 世界有“档位”（上限可配置）。  
- **存活王国**：在轮回结算后直接拿“世界档位”（视为满掌握度）。  
- **新建王国**：用“掌握度”来折算（0-100%）。  
- 新建王国生效档位 = `floor(世界档位 × 王国掌握度)`（最低档位可配置）。  

**掌握度计算**：  
- 公式：`掌握度 = 基础分 + Σ(指标分 × 权重)`
- 指标包括：书籍（文化/宗教/语言/首都/全城）、城市规模、人口、军力、建筑
- 阈值与权重见本节参数表

**使用时机**：  
- 新王国建立：按公式算"初始掌握度"
- 轮回结算后：**存活王国直接拿世界档位**（不走掌握度计算）
- 运行中：可选按“掌握度刷新间隔”定期更新

**覆灭/复国表现**：  
- 王国覆灭时，王国掌握度归零；世界档位不变。  
- 新王国若文化/宗教/书籍延续，则掌握度自然恢复；若书籍被毁/文化断层，则掌握度偏低。

#### 2.3.5 发放规则（结算时）

轮回结算时，系统只做“档位推进”：
- 所有遗产档位按配置推进（上限可配置），不做条件判定。
- 第 N 次轮回对应第 N 档（按配置档位推进）。

#### 2.3.6 实现要点（开发）

- 遗产用 `ActorTrait/KingdomTrait` 表达：王国用 `KingdomTrait`，魔王阵营用 `ActorTrait`。
- 解锁类遗产只扩展可用池，不直接叠加数值。
- 工艺遗产走原版“制作→库存→领取”流程，可提高英雄权重。
- 研究遗产走原版“随机特质”逻辑，按档位扩展候选池。
- 数值类遗产为被动加成，传承遗产在英雄晋升时写入。
- 装备/技能均为 MOD 自定义资产，生成时写入来源标记。

### 2.4 敌方军势（波次 / 将领 / 军团）
<a id="s24"></a>

敌方军势由“波次军团 + 将领 + 军团单位库”构成，负责节奏与压力梯度，覆盖预兆到封印战阶段。

**本节结构**
- 2.4.1 军团波次系统
- 2.4.2 将领系统（精英单位）
- 2.4.3 军团系统（单位库）
- 2.4.4 实现要点（开发）
- 2.4.5 参数表（可调）

#### 2.4.1 军团波次系统
<a id="s241"></a>

##### 2.4.1.1 核心概念

预兆阶段开始时立即生成第1波军团，之后按“军团_生成间隔”周期生成。随着波次增加，单位数量和强度逐步提升，给王国压力梯度。

**生成口径**：本节“实现要点（开发）”给出统一口径。

##### 2.4.1.2 波次生成规则

**波次模板（结构）**：按波次区间分段递进。

**强度递增公式**：
```
单波强度 = 基础强度 × (1 + 军团_强度递增 × 波次)
同时存在上限：由「军团_同时上限」控制
```

**单位来源**：每波从军团单位库抽取单位模板，生成数量与强度由参数表控制。

**遗迹战场热点（封印战调度）**：
- **战场热点调度**：系统定期从“魔王阵营”和“附近王国”各抽取小队，推动其向遗迹集结。
- **占领收益**：占领遗迹后，遗迹范围内友军获得小幅增益，促使双方主动争夺。
- **叠加规则**：同阵营多个遗迹收益不叠加，必要时设置叠加上限。
- **目标策略**：由“热点目标策略”决定波次集结目标，可选：优先敌占领/优先未占领/最近遗迹/随机。

#### 2.4.2 将领系统（详细）
<a id="s242"></a>

> 将领是“魔王侧的英雄单位”，用于把战局从“数量压制”变成“关键目标对抗”。  
> 统一槽位：每个将领 **P0 + S1**；技能触发与性能约束遵循「[统一口径](#conventions)」。

##### 2.4.2.1 通用规则（必须一致）

- **数量**：每个魔王固定 5 名将领。
- **激活**：苏醒阶段开始时，由轮回阶段推进触发，MOD自动执行生成逻辑，一次性生成全部 5 名将领；将领使用独立模板生成（不改造现存单位）。
- **生命周期**：每轮回只生成一次，死亡后不再补充；下一轮回重新生成新的 5 名将领（重置状态）。
- **生成地点**：优先在魔王据点或魔王附近的可行走地块生成；不足时在据点周边有限半径内补点；避开水域/山脉与封印遗迹范围。
- **技能触发与性能约束**：统一按附录A的口径执行；通用消耗与频率使用“技能与法力通用参数表”。
- **安全上限**：任何“范围枚举/召唤/地形改造”都必须有**单次触发上限**与**同时存在上限**（避免卡顿）。
- **平衡约束**（将领 < 魔王）：将领不做“全图效果/世界级事件/直接处决/真正免疫/永久控制”；控制类效果默认不超过 1 年（可被净化/驱散）

##### 2.4.2.2 将领名册与技能表

> 名册与技能表： [将领名册与技能表](将领名册与技能表.md#appendix-general-skills)。

##### 2.4.2.3 将领成长

- 成长公式：将领基础属性 = 基础值 × (1 + 轮回成长倍率 × 轮回数)。
- 基础值来源：生成时按「[2.7 主角单位属性随机范围](#s27)」写入随机基础值。
- 生效时机：轮回结算后生效，仅对下一轮回新生成的将领起效。
- 叠加顺序：随机基础值 → 轮回成长 → 特质/遗产加成。

#### 2.4.3 军团系统（单位库）
<a id="s243"></a>

> `2.4` 已定义波次与生成规则；本节补齐军团单位库的可实现口径：单位模板与生成规则。  
> 军团单位不配置技能，保持“自动生成小兵”的直观体验与性能稳定。

##### 2.4.3.1 军团通用规则（必须一致）

- **技能规则**：军团单位无技能（不挂载技能 trait），仅靠基础属性与模板区分。
- **同时上限**：受 `2.4` 的“军团_同时上限”约束；超过则停止生成。
- **模板口径**：见「[统一口径](#conventions)」。
- **死亡替换**：军团单位不做“永久变形”，需要“转化/同化”时用“替换生成”方式实现。
- **平衡约束**（军团 << 魔王）：军团不做“全图效果/复活/召唤自复制/直接处决/长期强控”。

##### 2.4.3.2 各魔王军团单位名册

名册见「[附录B](#appendix-legion-units)」。

##### 2.4.3.3 军团成长

- 轮回成长公式：军团基础属性 = 基础值 × (1 + 轮回成长倍率 × 轮回数)。
- 波次成长：单波强度随波次递增，规模与强度按波次规则计算。
- 基础值来源：生成时按「[2.7 主角单位属性随机范围](#s27)」写入随机基础值。
- 生效时机（轮回成长）：生成时一次写入，不改已生成单位。
- 生效时机（波次成长）：每次出波时计算规模与强度。
- 叠加顺序：随机基础值 → 轮回成长 → 波次强度换算 → 特质/遗产加成。

#### 2.4.4 实现要点（开发）

- 军团单位使用自定义 `ActorAsset` 直接生成，不改造现存单位。
- 生成入口：`ActorManager.spawnNewUnit(assetId, tile, ...)`。
- 生成地点：优先魔王据点附近成团生成并集结。
- 若据点不存在：在魔王附近或世界边缘可行走地块生成，再向最近王国推进。
- 生成点需可行走，必要时做小范围地形修正并限制次数。

### 2.5 王国与英雄系统
<a id="s25"></a>

王国与英雄构成抗魔反馈体系，并在魔王存活期触发世界停战与共同讨伐。

#### 2.5.1 抗魔等级（反馈机制）

王国通过与魔王战斗，逐步提升抗魔等级（上限可配置），形成“越战越强”的正反馈。  
本设计采用**生产级口径**：不修改底层伤害公式，而是通过“特质加成”实现“越打越能打”。
新王国诞生或者复国时，没有击杀过“魔王阵营单位”到一定数量，抗魔等级归零，一切从头开始。

**提升规则**：
```
累计击杀一定数量“魔王阵营单位”（本 MOD 生成） → 抗魔等级 +1
完成 1 次封印战结算（胜利）              → 抗魔等级获得额外加成
```

**效果（权威表）**：见本节“参数表”中的“抗魔等级档位效果”。

**实现要点（开发）**：
- 抗魔等级为王国维度数据，用 `KingdomTrait` 持久化。
- 加成只作用于全王国生物字段，避免改底层伤害公式。

#### 2.5.2 命定英雄

**产生规则**（晋升制）：
- 每个王国在每个轮回内有“命定英雄上限”。
- **触发方式**：事件触发为主 + 按“兜底检测间隔”定期检查（仅做条件检查，不强制晋升）。
- 当王国满足繁荣/危机阈值（人口、城市、战损等，**二选一/任一满足即可**；**统计范围=该王国自身**）时，系统从该王国现存单位中挑选 1 名候选并“晋升”为命定英雄：
  - 繁荣/危机阈值见本节参数表（与轮回阶段阈值可独立调整）
  - 优先：高等级/高击杀/寿命时间长/基础属性高的单位

**评分规则**（可配置）：
- **候选池过滤**：同王国、已成年、存活、非魔王/将领/军团、未被标记为英雄。
- **评分指标**：等级、击杀、寿命（或最大寿命）、最大生命、攻击、领导力（声望/指挥/组织）。
- **归一化**：将各指标归一化到 0-1。
- **加权求和**：按权重得到综合分。
- **晋升选择**：默认从前 N 名中随机 1 名，避免总是同一个人。
- **并列处理**：优先“击杀高 / 等级高”，仍相同则在前 N 名中随机。
- **兼容性**：若某项数据缺失，则忽略该项并把权重平均分给其他项，避免“没数据就被扣分”。

**评分公式**（默认口径）：
- 公式：`综合分 = Σ( min(指标/阈值, 1) × 权重 )`
- 阈值与权重见本节参数表（“英雄评分归一化阈值 / 英雄评分权重”）
- 计算顺序：归一化 → 加权求和 → 取前 N 随机

**命定英雄自带**：
- 命定英雄标记：用于识别/触发/日志，不提供基础属性加成
- “史诗表现”：独立头像/名字前后缀、表现层高亮与日志记录（不依赖行为树接管）
- 额外特质/技能按配置抽取

**命定英雄强化**（参数见本节参数表）：
- 英雄随机基础值：在“晋升为命定英雄”时按「[2.7 主角单位属性随机范围](#s27)」写入基础数值（只随机一次，不重抽）
- 法力上限、随机特质/技能数量等：见本节参数表
- 触发时机：仅在“晋升为命定英雄”时一次性写入（不做周期刷新）

**英雄随机特质池**（默认，可配置）：
- 抽取数量与规则见本节参数表
- 默认类型：生命/防御/对魔王伤害/移速/暴击/法力等增益
- 具体条目与字段口径见「[英雄专属随机池](英雄专属随机池.md#hero-traits)」

**英雄随机技能池**（规则，默认可配置）：
- **来源**：只从「[英雄专属随机池](英雄专属随机池.md#hero-skills)」抽取。
- **槽位口径**：命定英雄固定 P0「英勇」，S1 从技能池抽取（数量可配置）；普通英雄可选仅 P0。
- **抽取时机**：仅在“晋升瞬间”确定，不做周期重抽。
- **触发方式**：以命中/受击触发为主；消耗与频率写在英雄技能表内。

**家族继承**：
- **后代判定**：使用游戏内置 `Actor.data.parent_id` 字段识别后代关系（最多追溯3代）
- **触发时机**：英雄死亡时，遍历其后代，按概率触发继承（概率见本节参数表）
- **继承内容**：
  - 特质：直接复制到后代（可配置开关）
  - 技能：按配置复制到后代（可配置开关）
  - 属性：按比例继承（比例见本节参数表）
- **效果**：可形成"英雄家族"，延续故事线

**实现要点（开发）**：
- 英雄晋升通过 `Actor.addTrait(...)` 完成，并写入 MOD 英雄档案。
- 命定英雄标记使用 `trait_era_destined`，仅用于识别与日志。
- 技能 trait 不进入随机特质池，仅在生成或晋升时手动挂载。
- 法力读写使用 `Actor.getMana/getMaxMana` 与 `spendMana`。
- 触发频率在 trait 内用 `last_cast_year/casts_in_year` 记录。
- 触发条件使用可观测条件，不依赖任务 ID。
- 魔王影响区不做全局扫描，在命中/受击钩子内按距离判定。
- 家族继承用 `Actor.data.parent_id` 追溯，结果写入存档。

#### 2.5.3 世界停战与共同讨伐魔王阵营

> 目标：魔王存在期间，世界内部战争暂停，所有王国把“魔王阵营”视为共同敌人；封印后恢复各自外交与冲突，保证后续仍有剧情发展。

**触发条件**（魔王存活且任一满足）：
- 魔王进入「降临」阶段（可开关）；或
- 魔王摧毁世界城市比例超过阈值；或
- 世界人口跌破阈值且魔王仍存活（避免内耗导致局势失控）

**停战规则**：
- 触发时立即终止不包含魔王阵营的王国战争
- 停战持续到魔王被再封印
- 停战期间按固定间隔复查并终止新产生的王国间战争

**共同讨伐规则**（不建立世界联盟）：
- 魔王阵营为独立阵营，不建城、不发展、不参与外交
- 魔王阵营与所有王国保持战争关系
- **敌对范围**：魔王阵营的所有单位与生物
- **目标选择**：魔王阵营所有单位为目标

**封印后恢复**：
- 魔王被再封印后，移除停战标记并停止周期性停战处理；世界恢复正常外交与战争生成。

**实现要点（开发）**：
- 停战处理：遍历 `World.world.wars.getActiveWars()` 并结束非魔王阵营战争。
- 魔王阵营：用 `World.world.kingdoms.makeNewCivKingdom(...)` 创建独立阵营。
- 建战关系：进入停战时对各王国建战，建战前防重复。
- 停战标记：王国挂 `kingdom_trait_era_truce`，封印后移除。
- 目标选择：魔王阵营单位以非魔王阵营单位为目标。

### 2.6 叙事与事件系统（规则层）
<a id="s26"></a>

> 目标：把**真实发生的事件**整理成可读叙事，不编造、不乱序。

#### 2.6.1 数据来源（规则层）

- 世界历史/历史日志：`db.DBGetter.getWorldLogMessages()`
  - 关键字段：`timestamp / asset_id / kingdom_id / unit_id / x,y / special1-3`
  - 原文展示：`WorldLogMessageExtensions.getFormatedText(...)`
- 计划与阴谋：`World.world.plots`（`PlotManager`）
  - 关键字段：`Plot.getAsset()/getState()/getProgress()` 与 `PlotData.id_*`
- 战争：`MapBox.wars` 或 `WarManager.getActiveWars()`
  - 关键字段：`War.getAllAttackers()/getAllDefenders()`、`WarTypeAsset`
- MOD 自定义事件：魔王降临/封印/波次/英雄晋升等
  - 统一写入 `era_narrative_log`（JSON 或内存列表）

#### 2.6.2 统一事件结构（NarrativeEvent）

```
id: 全局唯一
year: 年份（与游戏年份对齐）
source: world_log / plot / war / mod
type: city_new / king_dead / war_started / demon_awake ...
entities: kingdom_id / city_id / unit_id / plot_id / war_id（可为空）
location: x,y（可为空）
raw_text: 游戏内原文或短句摘要
importance: 重要度分（用于章节选材）
```

**存储建议**：
- 运行态：内存列表 + `last_year/last_timestamp`
- 持久化：随 MOD 存档写入 JSON，读档可恢复

#### 2.6.3 生成流程（保证逻辑一致）

1) **增量采集**：记录 `last_year/last_timestamp`，只拉取新增事件。
2) **标准化**：统一成 `NarrativeEvent` 结构。
3) **实体时间线校验**：维护 `dead_at`，死亡/覆灭后不得再出现后续行为。
4) **排序分章**：按年份严格排序，可按阶段或年份跨度分组。
5) **生成叙事**：无 LLM 用模板，有 LLM 仅润色与串联。

#### 2.6.4 无 LLM 模式（稳定可跑）

规则：**只用真实事件原文 + 少量连接词**。

模板示例：
- 城市建立：`{year} 年，{city_name} 建立。`
- 王国建立：`{year} 年，{kingdom_name} 建国。`
- 战争开始：`{year} 年，{attacker} 与 {defender} 开战。`
- 同年事件可用“同年/与此同时”，跨年用“次年/若干年后”。

#### 2.6.5 LLM 模式（受强约束）

- 不得新增人物/地点/时间
- 不得改变先后与因果
- 每段必须能追溯到事件来源（带 `event_ids`）

**输入（结构化事实）**：
```
events: [{ id, year, type, raw_text, entities, location }]
rules: ["不得新增人物/地点/时间", "不得改变先后与因果", "每句必须引用 event_ids"]
```

**输出（可校验）**：
```
paragraphs: [{ text: "...", event_ids: [1,2,3] }]
```

#### 2.6.6 一致性规则（强制）

- **真实优先**：无法验证的内容不写
- **时间有序**：严格按年份排列
- **角色不乱写**：没有明确凶手就不写“谁杀了谁”
- **可追溯**：每章保留事件来源列表
- **稳定退路**：LLM 失败立即回退模板叙事
- **事件校验**：事件 ID 必须存在且顺序正确

### 2.7 主角单位属性随机范围（通用）
<a id="s27"></a>

> 目标：生成时直接写入基础数值区间，减少倍率叠加，保留个体差异。

- **适用对象**：仅对本 MOD 自定义单位生效（魔王/将领/军团/英雄）。
- **随机时机**：魔王/将领在生成时随机一次；军团在每个波次开始时随机一次并共享；英雄在晋升时随机一次。
- **作用字段**：`health/armor/damage/speed/attack_speed` 写入 `base_stats`；`critical_chance` 写入绝对百分比值。
- **覆盖规则**：模板同名字段在生成时会被随机值覆盖。
- **叠加顺序**：先写入随机基础值，再叠加轮回成长/特质/遗产加成。
- **参数规则**：统一见「[附录A](#conventions)」的配置与容错口径。
- **初始范围**：下表为第 1 轮范围。

| 单位类型 | 生命 | 防御 | 伤害 | 暴击率 | 移速 | 攻速 | 时机 |
|---------|------|------|------|--------|------|------|------|
| 魔王 | 80000~200000 | 400~1000 | 800~2000 | 8%~25% | 8~12 | 0.8~1.2 | 生成时 |
| 将领 | 4000~12000 | 80~250 | 200~500 | 6%~18% | 10~15 | 0.9~1.3 | 生成时 |
| 军团 | 200~1200 | 10~80 | 20~120 | 2%~10% | 9~13 | 0.9~1.3 | 生成时 |
| 英雄 | 2000~8000 | 50~200 | 120~350 | 6%~18% | 10~14 | 0.9~1.3 | 晋升时 |

> 生命/防御/伤害/移速/攻速为**绝对数值区间**，暴击率为**绝对百分比**。

#### 2.7.1 随机范围平移

- **定义**：用本轮随机平均值作为下一轮下限，上限保持初始宽度。
- **初始宽度**：初始宽度=初始上限-初始下限，后续不变化。
- **生效时机**：轮回结算时写入下一轮范围。
- **魔王平均**：本轮所有魔王的随机结果取平均，作为下一轮魔王范围下限。
- **将领平均**：本轮所有将领的随机结果取平均，作为下一轮将领范围下限。
- **军团平均**：本轮波次基准值取平均，作为下一轮军团范围下限。
- **波次基准值**：每个波次开始时随机一次，同一波次单位共享。
- **未生成处理**：本轮未生成该类型单位时，下一轮沿用当前范围。
- **玩家改动**：玩家手动改范围后，清零偏移并以新范围重新计算。
- **适用对象**：本规则只对魔王/将领/军团生效，英雄仍按当前范围随机一次。
- **显示**：UI 显示本轮的实际范围。

| 参数组 | 可调控（UI） | 说明 | 使用章节 |
|------|-----|------|------|
| 法力消耗 | 主动技能法力消耗（固定-普通）：数值（5点数）；主动技能法力消耗（固定-终极）：数值（10点数） | 主动技能消耗 | 2.8/通用 |

  - 展示方式：表格形式，标注"新增/修改/删除"
  - 冲突处理：标注不兼容项（如版本不匹配、数值超出范围），提示用户确认
  - 预览界面：显示"参数名 | 旧值 | 新值 | 状态"四列

**预设**
- 预设 = 命名的一组参数（常用组合一键切换）
- 支持：保存当前为预设 / 应用预设 / 删除预设
- 预设可一键导出分享（本质仍是参数文件）

**生效时机**
- 导入后立即刷新 UI
- 实际生效遵循每个参数的“立即生效/下轮回生效”规则

**实现要点（开发）**：
- 配置文件为 JSON，必须包含 `config_version`。
- 导出仅包含可在 UI 调整的参数，剔除敏感字段。
- 导入流程：读取 → 版本校验/迁移 → 差异预览 → 校验修正 → 应用。
- 未知字段忽略，缺失字段补默认，非法值按附录A容错修正。
- 应用前备份当前配置，失败回退并提示。

### 4.3 资产注册与自动生成（实现口径）

本 MOD 采用“自定义生成”为默认策略：魔王/将领/军团/关键建筑均由 MOD 自动生成，避免依赖随机抽取现存单位导致的行为不可控与兼容性问题。

**资产注册（启动时）**：
- 单位：注册魔王/将领/军团等自定义单位模板（`ActorAsset`）到 `AssetManager.actor_library`
- 特性：注册遗产、感染、标记、护盾等自定义 `ActorTrait/KingdomTrait` 到 `AssetManager.traits`（用于 `action_attack_target / action_on_object_remove` 等钩子）
- 建筑：注册封印遗迹/魔王据点等自定义建筑模板（`BuildingAsset`）到 `AssetManager.buildings`

**实体生成（运行时）**：
- 生成单位：通过 `ActorManager.spawnNewUnit(assetId, tile, ...)` 在目标地块直接生成新的 `Actor`
- 生成自定义建筑：【需反射】调用 `World.world.buildings` 的 `internal addBuilding(...)` 直接放置；并用 `WorldTile.setTileType/setTopTileType/removeTrees/removeGrass` 做小范围视觉表现
- 自动选点：根据类型偏好地形与“可行走/空间足够”等条件选点；不满足时在有限半径内做小范围地形修正后生成目标建筑（严格限制频率与次数）

### 4.5 可自定义外观/特效清单（已确认）

> 目标：明确“哪些外观/特效可以做成**王国自研/魔王自研**”，不留模糊说法。

**确认可做（全部为 MOD 自定义，不是原版改名）**：
- **单位外观与动画**（魔王/将领/军团/英雄）：自定义 `ActorAsset` + 自定义贴图（`ToolBox.LoadSprite()`）；动画基于**精灵帧**（sprite sheet），可替换为自定义帧序列。
- **装备外观与能力**（王国工艺/魔王军备）：自定义 `ItemAsset` + 自定义贴图 + 自定义数值与特效（通过装备绑定 trait 实现命中/受击效果）。
- **建筑/遗迹外观**：自定义 `BuildingAsset` + 自定义贴图与说明；配合小范围地形变化做表现。封印遗迹支持状态特效（待机/可占领/已占领/被打断），用 `EffectAsset` + `EffectsLibrary.spawn(...)` 实现。
- **技能特效**：可用 `EffectAsset` + `EffectsLibrary.spawn(...)` 生成自定义特效（自带 sprite 与播放参数），并由 trait/ActionLibrary 触发。
- **命名与叙事标记**：装备/技能可写入“制造王国/制作者/研发年份”，用于叙事可追溯。

**明确不做（删除承诺）**：
- **自定义音效**：不做新的音效资源加载，仅复用游戏内已有 `sound_*` 标识。  
- **骨骼/模型级动画替换**：游戏为 2D 精灵帧体系，不引入骨骼/3D 动画替换。

**实现原则（统一口径）**：
- “自研”= 使用 MOD 自定义资产（`ActorAsset/ItemAsset/BuildingAsset/EffectAsset`），不是改原版名字。  
- “特效”= 绑定 trait 与现有动作组合实现，确保可落地。

## 附录A：统一口径与实现约定

（速览入口已前移到《使用指南》，此处提供完整细则。）

<details>
<summary>展开详细约定（触发/存储/数值/配置/生成/技能资源/排版）</summary>

**A. 时间与触发**
- 时间单位（系统节奏）：轮回/阶段/事件池用游戏内“年份”（对齐 `Date.getCurrentYear()`）。
- 技能部分不做“每年结算/定时器轮询”：系统层面（轮回推进/波次调度）可用低频定时，但技能效果只允许走三种 action 钩子触发（命中/受击/死亡点）。

**B. 事件触发与状态存储**
- 命中触发：攻击者挂自定义 `ActorTrait`，用 `ActorTrait.action_attack_target`（`AttackAction`）拿到 `pSelf/pTarget/pTile`。
- 受击触发：受击者挂 trait/status，用 `action_get_hit`（`GetHitAction`）拿到 `pSelf/pAttackedBy/pTile`。
- 死亡点触发：命中时给目标挂短时标记 trait → 标记 trait 的 `action_on_object_remove`（`WorldActionTrait`）在目标死亡/移除时生成效果。
- 实现手段：优先用 `ActionLibrary.*`（眩晕/传送/雷击等）；没有现成动作时再用自定义 trait + `custom_data_*` 存状态。
- 层数/持续/限频存储：优先写 `custom_data_int/custom_data_float`（如 `era_contract_stacks` / `era_contract_expire_year` / `era_proc_count`）。到期清理与限频检查只在三钩子里做（不额外开“每年扫描名单/定时器表”）。
- 范围效果（允许但要写清楚）：只能在钩子触发时，以 `pTile` 为中心枚举有限半径对象（如半径 8/12）；禁止全图扫描/维护感染名单/每年遍历全体单位。

**C. 数值口径（UI 与配置统一）**
- 百分比：`0%-100%` 或 `+15%`。
- 伤害：百分比伤害统一按 `当前生命（health_current）` 计算，默认“最低扣到 1HP”（除非另有说明）。
- 伤害倍率口径：技能里出现“伤害 ×N / 伤害 +X%”时，默认以基础伤害 `damage` 为基准（可配置）。
- 基础属性字段：`damage`=伤害，`damage_range`=伤害浮动，`armor`=防御，`health`=最大生命，`speed`=移速，`attack_speed`=攻速，`critical_chance`=暴击率，`critical_damage_multiplier`=暴击倍率，`lifespan`=寿命（年），`multiplier_lifespan`=寿命倍率。
- HP 百分比口径：`health_current_pct`=当前生命百分比，`health_max_pct`=最大生命百分比。技能描述中的“当前生命/最大生命”默认对应这两个字段。

**D. 配置与容错**
- 技能参数可配置：伤害、百分比、持续、半径、次数、概率、上限、法力消耗、频率等默认进入配置与 UI，可随时调整。
- 可配置口径：标记为“可调项”的参数进入配置文件与控制面板；非法值（空/NaN/≤0 间隔/超大值）需做安全修正并提示（不崩溃）。
- 配置文件导入/导出：JSON 格式；必须包含 `config_version`；缺字段用默认、未知字段忽略；非法值按本节规则修正；版本不兼容时尝试迁移，失败则回退并提示；导出时不包含敏感字段（如 API Key）。
- 时间/数量类：小于 0 的输入按 0 处理。
- 间隔类：`<= 0` 自动修正为最小正值（避免除零/死循环）。
- 概率类：按 `0%-100%` 归一（超过 100% 视为 100%；小于 0 按 0 处理）。
- 任意数值：若出现 `NaN/Infinity` 自动回退为安全值。
- 范围类（min/max）：若 `min > max` 自动互换。
- 倍率类：`<= 0` 修正为最小正值。
- 暴击率：`critical_chance` 最终按 `0%-100%` 归一。
- 数值上限：默认不强制上限，但极端值可能影响平衡与性能。

**E. 生成与挂载**
- 技能槽位口径：魔王为 `P0 + S1-S6`；将领为 `P0 + S1`；军团无技能。除特别声明外，控制类效果应短时且有上限。
- 生成口径：魔王/将领/军团使用独立 `ActorAsset` 模板自定义生成（可从原生模板 clone 后改 `id/sprite/数值`）；不直接改写原生资产，不通过“现场改造现存单位”的方式生成。
- 模板基底：选用“原生可见法力条”的基底（避免 `force_hide_mana`），以便技能直接使用游戏内置 `Actor.mana`。
- 技能挂载口径（防误扩散）：技能 trait 不加入随机特质池/出生池，仅在生成魔王/将领或晋升命定英雄时由代码手动 `addTrait(...)` 挂载；军团不挂技能 trait。
- 随机特质口径（普通 trait）：魔王/将领/军团/命定英雄与原版单位一致，可通过 `rate_birth/rate_acquire_grow_up/rate_inherit` 自动获得普通特质（非技能 trait）；走游戏自身的特质编辑器逻辑；默认开启，可配置关闭。
- 寿命口径（魔王阵营）：魔王/将领/军团默认“不老死”，在 `ActorAsset.base_stats` 上将 `lifespan` 设为超大值（或 `multiplier_lifespan` 设为超高倍率）。

**F. 技能资源与消耗**
- 主动技能不使用传统冷却条，统一用法力作为资源，并有触发频率上限。
- 默认消耗与频率参数使用“技能与法力通用参数表”，此处不重复；可按技能单独覆盖。

**G. 收藏与排版**
- 收藏标记口径（便于定位）：生成魔王/将领/命定英雄时可自动加入收藏夹（配置开关）；默认不收藏普通军团。实现：`ActorAsset.can_be_favorited=true` + `Actor.switchFavorite()`。单位死亡后会被销毁，不需要额外“手动取消收藏”。
