## Context

- 现状：`EraWheel_Redesign.md` 体量大，存在内容跳跃、重复、口径分散、章节错位等问题，阅读成本高。
- 约束：不改变既有规则与含义，只调整结构与表述；合并/删除/移动必须干净，不留残留痕迹。
- 读者：开发与玩家混合，需要“开发规则清晰 + 玩家理解直观”。
- 依赖：文档内大量锚点与附录引用，需要保持可用或同步更新。

## Goals / Non-Goals

**Goals:**
- 建立清晰的信息分层：使用指南 → 正文系统 → 附录大表。
- 合并重复描述，保留唯一权威口径。
- 统一章节模板（概念→触发→持续→表现→结束→参数入口）。
- 规范默认值与参数入口的归属，避免正文与附录冲突。
- 修复错位内容，让相关内容归位并顺畅阅读。

**Non-Goals:**
- 不修改玩法规则、数值含义与技术可行性结论。
- 不新增功能、不改代码、不引入新的外部依赖。
- 不重写附录大表的具体数据（除非为去重而移动位置）。

## Decisions

1) **三层结构固定化**
- 决策：把“阅读提示、快速入口、统一口径说明”集中到使用指南；正文只讲规则；附录只放大表。
- 备选：在每章前重复提示。放弃原因：重复与口径漂移。

2) **唯一权威口径规则**
- 决策：默认值只在第七部分；技能/名册/字段只在附录；实现口径集中在附录A与第五部分“实现要点”。
- 备选：正文与附录同时给默认值。放弃原因：冲突风险高。

3) **章节模板统一**
- 决策：系统细节统一“概念→触发→持续→表现→结束→参数入口表”。
- 备选：自由叙述。放弃原因：阅读体验不一致，难检索。

4) **锚点与引用处理**
- 决策：优先保留现有锚点 ID；若移动章节导致失效，则同步更新目录与所有引用。
- 备选：重新编号全部锚点。放弃原因：外部引用风险高。

## Risks / Trade-offs

- [锚点失效] → 迁移后统一检查目录与引用，必要时保留旧锚点作为兼容入口。
- [内容误删] → 以“唯一权威”对照清单逐条核对，确保规则不丢失。
- [描述变形] → 仅改表述与结构，不改规则含义；关键句可与原文对照确认。
- [与对外文档不一致] → 明确是否需要同步另一份文档，必要时增加“同步/弃用”说明。

## Migration Plan

- 先生成“结构草案 + 合并/移动/删除清单”。
- 在 `EraWheel_Redesign.md` 逐节重排并统一口径。
- 最后全局校验：目录可点击、引用可追踪、默认值唯一来源。
