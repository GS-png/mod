## ADDED Requirements

### Requirement: 文档结构按统一顺序重排
文档 MUST 按“使用指南 → 项目概述 → 玩法闭环 → 系统细节 → 数值与平衡 → 用户交互与配置 → 技术可行性与实现方案 → 版本规划与交付 → 关键参数默认值速查 → 附录”顺序组织。

#### Scenario: 章节顺序检查
- **WHEN** 读者查看目录与正文
- **THEN** 章节顺序与上述统一顺序一致

### Requirement: 统一口径提示语集中到使用指南
所有“默认值只在第七部分/实现口径见第五部分/流程权威来源”等提示 MUST 只在“使用指南”集中出现一次，正文不重复。

#### Scenario: 提示语出现位置
- **WHEN** 读者检索提示语
- **THEN** 仅在“使用指南”找到统一提示

### Requirement: 重复内容合并为唯一权威
针对相同目标或含义重复出现的内容，文档 MUST 合并为一个权威表述，其它重复段落必须删除或融入该权威表述。

#### Scenario: 重复段落处理
- **WHEN** 读者对比重复内容
- **THEN** 只存在一个权威版本，其它重复内容已被删除或融合

### Requirement: 错位内容归位到正确章节
任何不属于当前章节主题的描述 MUST 移动到对应的正确章节。

#### Scenario: 章节主题一致性
- **WHEN** 读者逐节阅读
- **THEN** 每节内容与其标题主题一致

### Requirement: 系统章节采用统一段落模板
系统类章节 MUST 统一使用“概念→触发→持续→表现→结束→参数入口→实现引用”的段落模板（按需出现，但顺序保持一致）。

#### Scenario: 模板一致性
- **WHEN** 读者查看系统章节
- **THEN** 每节段落顺序与模板一致

### Requirement: 保留玩家/开发双线提示但不打断主线
文档 MUST 保留“玩家视角/开发视角”双线信息，但以节末简短提示呈现，不插入主线正文中段。

#### Scenario: 双线提示位置
- **WHEN** 读者阅读正文段落
- **THEN** 玩家/开发提示出现在章节末尾的简短提示区

### Requirement: 目录与锚点引用保持有效
目录与正文锚点 MUST 一致，跳转链接必须指向正确章节位置。

#### Scenario: 目录跳转验证
- **WHEN** 读者点击目录条目
- **THEN** 跳转到对应章节的正确位置
