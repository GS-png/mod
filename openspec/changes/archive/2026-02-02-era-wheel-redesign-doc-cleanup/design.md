## Context

- 目标文档：`EraWheel_Redesign.md`
- 现状问题：重复描述、章节错位、口径不统一、锚点跳转不稳定，读者难以在一次阅读中形成完整理解
- 约束：只整理文档，不改代码与实现；合并必须“融为一体并删除旧内容”，不得留下引用残留

## Goals / Non-Goals

**Goals:**
- 建立唯一权威口径：阶段、参数、技能表、遗产表、实现口径各归一处
- 降低阅读成本：内容顺序连贯，读者知道“规则在哪、参数在哪、表格在哪”
- 可维护：后续改动只需改一处，不产生歧义

**Non-Goals:**
- 不新增玩法或改动数值逻辑
- 不改代码实现、不新增资源、不改变对外 API

## Decisions

1) **唯一权威放置**
- 规则只在第二部分；参数只在第七部分；实现细节只在第五部分；大表只在附录
- 原因：避免多处维护与口径冲突
- 备选：在正文多处保留“示例/摘要” → 放弃，易导致重复与冲突

2) **参数索引方式（A + C）**
- 每个系统小节末尾保留“参数入口表（无数值）”
- 第七部分参数表新增“使用章节”列
- 原因：读者既能从规则找到参数，也能从参数反查规则，且不重复默认值
- 备选：仅在开头提示“见第七部分” → 放弃，缺少定位与上下文

3) **合并规则**
- A+B 合并为新 C 并删除 A/B；或 A 融入 B 并删除 A
- 仅保留必要跳转（例如附录大表、默认值表）
- 原因：避免遗留痕迹与重复内容

4) **阶段流程图唯一化**
- 把阶段流程图与阶段触发放到 2.1.2 作为唯一权威
- 其他章节仅保留一句“见 2.1.2”

## Risks / Trade-offs

- **风险：锚点或目录断链** → 逐条复核目录与锚点跳转，更新全部引用
- **风险：合并时遗漏细节** → 合并前列清单，合并后全文检索确认仅剩一处
- **权衡：减少重复可能降低快速扫读** → 用“参数入口表”和“附录索引”补足快速定位

- 逐段合并与归位，完成后修复目录与锚点
