## Context

- 目标文件是 `EraWheel_Redesign.md`，体量大，内容分散。
- 规则、实现、参数分散在 2.x/5.x/7.x，阅读跳转多。
- 需求是整理为结构清晰、唯一权威的单文件文档。
- 约束：不改玩法与数值，不同步其他文档。

## Goals / Non-Goals

**Goals:**
- 重排章节顺序，让阅读路径直观。
- 同一规则只保留一个权威位置。
- 默认值与实现入口回收到系统小节。
- 更新目录与锚点，保证跳转可用。
- 保持内容完整，不引入新规则。

**Non-Goals:**
- 不更改玩法目标与数值。
- 不更新其他文档与代码。
- 不新增新的系统或功能。

## Decisions

1) 继续使用单文件，不拆分多文档。
- 备选：拆分为规则/参数/实现多个文件。
- 选择理由：减少跨文件跳转，符合“单一权威”。

2) 采用固定分区顺序：概述 → 核心系统 → 玩家 UI → 技术基础 → 版本规划 → 附录。
- 备选：保留现有章节顺序。
- 选择理由：与读者心智一致，减少回跳。

3) 规则+默认值+实现入口放在同一系统小节。
- 备选：保留第七部分默认值速查。
- 选择理由：避免“正文讲规则，参数在别处”。

4) 附录只保留大表与统一口径细则。
- 备选：在正文重复表格与口径。
- 选择理由：减少重复，降低冲突风险。

5) 目录与锚点同步更新，保证唯一且可跳转。
- 备选：只移动内容，不改锚点。
- 选择理由：旧锚点易失效，必须同步。

## Risks / Trade-offs

- 锚点变化导致外部引用失效 → 统一更新目录与链接。
- 内容移动遗漏 → 使用“移动/合并清单”逐条核对。
- 合并后仍残留重复段落 → 全文搜索关键词复查。
- 读者适应新结构需要时间 → 在“使用指南”给出新阅读顺序。

## Migration Plan

1) 备份 `EraWheel_Redesign.md`。
2) 按清单移动与合并段落。
3) 删除旧位置残留内容。
4) 重写目录与快速入口。
5) 全文检查锚点与跳转。
