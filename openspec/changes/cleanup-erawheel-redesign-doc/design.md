## Context

`EraWheel_Redesign.md` 内容量大、重复多、口径不一致，开发与玩家阅读负担高，容易在实现时产生误解。需要在不改变玩法目标的前提下，整理为结构清晰、唯一权威、便于查阅的版本。

## Goals / Non-Goals

**Goals:**
- 形成稳定、可检索的文档结构（阅读顺序清晰）
- 规则与默认值归属明确（正文讲规则，数值集中到第七部分/附录）
- 解决已知冲突点并避免重复
- 补齐已描述但缺实现口径的内容（导入/导出、继承、模式切换）

**Non-Goals:**
- 不修改玩法系统与数值逻辑本身
- 不进行代码实现或接口变更
- 不新增与本次整理无关的新功能

## Decisions

1. **保持“1-7 + 附录”的总体结构**，但重排内容位置，使规则先行、实现口径后置、数值集中。
   - 备选：拆分为“玩家版/开发版”双文档。未选用，先在单文档内用章节隔离。

2. **“唯一权威”原则落地**：
   - 正文只讲规则与流程；默认值只在第七部分/附录出现；实现口径集中到第五部分/附录A。
   - 备选：在正文保留部分默认值。未选用，避免重复与冲突。

3. **冲突点统一**：
   - 封印胜利方式统一为“双通道”。
   - 英雄“闪现”统一为“持续 1 年、移速 +10%”。

4. **叙事系统规则前移**：
   - 规则/流程放第二部分；实现口径仍放第五部分，减少跳转。

## Risks / Trade-offs

- [风险] 重排可能导致锚点失效 → [缓解] 更新目录与快速入口、全量检查链接
- [风险] 合并删除时误删必要信息 → [缓解] 先做“去重清单”，逐条核对
- [权衡] 单文档同时面向玩家与开发 → [缓解] 明确章节定位与阅读指引

## Migration Plan

- 原地整理 `EraWheel_Redesign.md`，不拆分文件
- 调整目录与锚点后进行通读与一致性检查
- 保留修改前备份（如需要可另存旧版文件）
