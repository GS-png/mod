## ADDED Requirements

### Requirement: 文档结构与阅读顺序固定
文档 MUST 维持清晰的顶层结构：使用指南、术语速查、第一至第七部分、附录；并在使用指南中给出推荐阅读顺序。

#### Scenario: 目录与阅读顺序可直接对齐
- **WHEN** 读者查看目录与使用指南
- **THEN** 目录顺序与推荐阅读顺序不冲突，且能在 1-2 次跳转内到达关键章节

### Requirement: 默认值唯一权威归属
所有可调参数与数值默认值 MUST 仅出现在“第七部分/附录表”，正文只保留规则与入口链接，不重复给出具体数值。

#### Scenario: 正文不再出现默认数值
- **WHEN** 读者阅读第一至第五部分
- **THEN** 不会看到默认数值，只能看到规则描述与指向第七部分/附录的链接

### Requirement: 附录与大表不重复
每个附录表（技能表、名册、字段表、遗产表等）MUST 仅出现一次，正文不得复制同表内容。

#### Scenario: 同一大表只有一处权威出现
- **WHEN** 检索附录关键标题
- **THEN** 仅命中一处定义位置，不出现重复表格

### Requirement: 关键冲突点口径统一
文档 MUST 统一以下口径：
- 封印胜利方式为“双通道”（击杀/仪式任一达成即胜）
- 英雄“闪现”为“持续 1 年、移速 +10%”

#### Scenario: 全文表述一致
- **WHEN** 读者在全篇搜索“封印胜利方式/闪现”
- **THEN** 只能看到上述统一口径，不出现其他数值或方式

### Requirement: 已描述内容补齐实现口径
文档 MUST 补齐此前仅有描述但缺实现口径的内容：参数导入/导出与预设、英雄家族继承、模式切换（玩家/高级/开发）。

#### Scenario: 第五部分包含对应实现口径
- **WHEN** 读者查看第五部分技术可行性与实现方案
- **THEN** 能找到上述三项的实现口径说明与边界约束
