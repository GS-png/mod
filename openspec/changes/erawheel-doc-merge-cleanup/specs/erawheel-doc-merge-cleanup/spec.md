## ADDED Requirements

### Requirement: 文档结构统一且线性
整理后的文档 MUST 按“使用指南 → 概述 → 玩法闭环 → 系统细节 → 数值与平衡 → 用户交互与配置 → 技术可行性与实现方案 → 版本规划与验收 → 关键参数默认值速查 → 附录”的顺序组织，不再交叉跳读。

#### Scenario: 章节顺序可一眼验证
- **WHEN** 读者从目录查看大章顺序
- **THEN** 目录顺序与上述线性结构一致

### Requirement: 合并后删除源文且不留残留引用
重复内容 MUST 通过“合并成新段落”或“并入目标段落”完成，并删除源段落；除“附录大表/默认值速查”的必要链接外，正文不得保留“详见/参见”残留。

#### Scenario: 合并不留痕
- **WHEN** 两处内容表达同一规则
- **THEN** 规则只保留一处完整表述，其他位置不保留引用或残段

### Requirement: 唯一权威口径
每条规则/口径 MUST 只有一个权威位置；其他位置不得重复完整叙述，只允许必要的简短提示或目录索引。

#### Scenario: 规则不再重复
- **WHEN** 读者检索同一规则
- **THEN** 只能在一个位置找到完整权威描述

### Requirement: 错位内容归位
所有内容 MUST 出现在语义一致的章节中，例如 UI 说明仅在“用户交互与配置”，技术实现仅在“技术可行性与实现方案”。

#### Scenario: 错位段落被移动
- **WHEN** 发现某段落属于 UI/技术/数值范畴
- **THEN** 该段落被移动到对应章节而非保留在原位置

### Requirement: 默认值集中
默认值 MUST 只出现在“关键参数默认值速查”章节；正文仅保留参数入口或规则说明，不重复默认值。

#### Scenario: 默认值不分散
- **WHEN** 读者在正文查找默认值
- **THEN** 只能在“关键参数默认值速查”中看到默认值

### Requirement: 目录与锚点可用
目录和锚点 MUST 与正文一致，所有目录链接都能跳转到正确位置。

#### Scenario: 目录跳转无失效
- **WHEN** 点击任意目录链接
- **THEN** 跳转到对应章节标题

### Requirement: 语义不改变
整理过程中 MUST 不改变玩法规则、默认数值或实现口径的含义，仅做重排与表述优化。

#### Scenario: 规则含义保持一致
- **WHEN** 对比整理前后同一规则
- **THEN** 含义与数值保持一致

### Requirement: 提示语收敛且简洁
玩家/开发提示 MUST 收敛为大章末尾的简短提示，不在小节反复出现。

#### Scenario: 提示语密度降低
- **WHEN** 读者通读某系统章节
- **THEN** 仅在该大章末尾看到简短提示
