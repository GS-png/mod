## Context

- 目标文档：`EraWheel_Redesign.md`（约 2300+ 行）。
- 当前问题：内容重复、错位、跳读与提示语堆叠，导致阅读成本高且容易误解口径。
- 约束：不改变玩法含义与默认值，不新增机制，不改代码；只做结构整理与表达优化。
- 额外规则：合并必须“融合后删除源文”，不留引用残痕，除非必须链接附录/默认值。

## Goals / Non-Goals

**Goals:**
- 形成清晰的阅读路径与一致的章节顺序。
- 合并重复内容并删除源文，建立唯一权威描述。
- 把错位内容归位到正确章节，减少跳读。
- 统一写法与提示语密度，让文档干净、简洁、具体且完整。
- 更新目录与锚点，保证跳转可用。

**Non-Goals:**
- 不改动任何规则含义、数值默认值或系统功能。
- 不新增或删除玩法机制。
- 不改变实现口径的技术事实（仅移动与整理）。
- 不修改代码与资源文件。

## Decisions

1. **重排为固定大纲顺序**
   - 选择：使用“使用指南 → 概述 → 玩法闭环 → 系统细节 → 数值 → UI → 技术 → 版本 → 默认值 → 附录”的线性结构。
   - 理由：读者先建立整体，再逐层深入，减少跳读。
   - 备选：保留原顺序，仅做局部移动。缺点是重复与错位难以根治。

2. **合并后删除源文，不保留残留引用**
   - 选择：A+B 融合为新 C 或并入 B 后删除 A；仅在“必须指向附录大表/默认值区”时保留链接。
   - 理由：避免“表面去重但实际仍需跳转拼接”。
   - 备选：保留引用链。缺点是读者仍需来回查找。

3. **默认值集中、口径集中**
   - 选择：默认值只在“关键参数默认值速查”；触发/存储/三钩子等口径只在附录A。
   - 理由：避免正文重复与冲突。
   - 备选：正文保留一部分默认值，易造成多处冲突。

4. **提示语收敛到“章节末尾简短提示”**
   - 选择：每个大章只保留一条玩家/开发提示，不在小节反复出现。
   - 理由：减少噪音，保持可读性。
   - 备选：每节保留提示，造成阅读干扰。

## Risks / Trade-offs

- [风险] 合并时遗漏细节 → [缓解] 先列“移动/合并/删除清单”，逐条对照保留要点。
- [风险] 目录与锚点失效 → [缓解] 重排后统一校验目录链接。
- [取舍] 文本更短但信息密度更高 → [缓解] 保留“快速入口/索引表”帮助检索。

## Migration Plan

1. 通读全文并生成“移动/合并/删除清单”。
2. 按新顺序重排章节与子节。
3. 执行合并：生成新段落后删除源段落，不留残留引用。
4. 统一提示语密度与模板结构。
5. 更新目录与锚点，通读自检。
