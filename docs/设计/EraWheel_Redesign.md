# 文档信息与阅读路线
- 名称：纪元之轮：魔王轮回 MOD 设计总览。
- 编号：`ERA-WHEEL-DEMON-MOD`。
- 版本：`2.6`。
- 更新：`2026-04-07`。
- 目标平台：`WorldBox 0.51.2+`（`NeoModLoader`）。

## 这是什么 MOD
- EraWheel 是一个围绕“魔王来袭 -> 世界应战 -> 战后成长 -> 下一轮再战”展开的长期循环 MOD。
- 玩家不是只盯一场战斗，而是在看整个世界一次次顶住危机、留下积累、再面对更强敌人。
- 这份文档现在只负责讲清玩法总览、系统职责和阅读入口；详细参数、条目名册和开发实现已经拆到独立文档。

## 一轮游戏怎么走
1. 世界先进入 `预发展`，像平时一样扩人口、建城市、慢慢长大。
2. 人口达到阈值后进入 `预兆`，系统确定本轮魔王名单，生成据点，军团开始出波，将领封印开始衰减。
3. 将领封印归零后进入 `苏醒`，将领正式登场，魔王封印继续衰减。
4. 魔王封印归零后进入 `降临`，魔王实体出现并主动进攻，战场压力来到最高点。
5. 击败最后一名存活魔王后进入 `战后重建`，系统结算奖励、发放轮回进阶、写历史，然后开启下一轮。
- 本 MOD 的胜利条件很简单：把这一轮的魔王打完。
- 如果这一轮同时苏醒了多名魔王，就要等最后一名存活魔王倒下，整轮才算赢。

# 玩法闭环

## 阶段闭环表
| 阶段 | 进入条件 | 这一段玩家最关心什么 | 退出条件 |
|---|---|---|---|
| 预发展 | 新档开始，或上一轮战后重建完成 | 世界有没有长到危险阈值；王国有没有站稳脚跟 | 世界人口达到预兆阈值 |
| 预兆 | 人口达到阈值 | 本轮会来哪些魔王；据点落在哪里；军团开始出波 | 将领封印降到 `0%` |
| 苏醒 | 将领封印降到 `0%` | 将领已经上场，战线开始被顶住还是被冲垮 | 魔王封印降到 `0%` |
| 降临 | 魔王封印降到 `0%` | 魔王本体入场，军团加速，整轮压力最高 | 最后一名存活魔王被击败 |
| 战后重建 | 本轮胜利 | 轮回奖励发了什么；幸存者留下了什么；下一轮会更强到什么程度 | 状态重置完成，回到预发展 |

## 阶段职责矩阵
| 阶段 | 将领状态 | 军团节奏 | 玩家体感 |
|---|---|---|---|
| 预发展 | 不生成 | 关闭 | 世界在积蓄力量。 |
| 预兆 | 不生成；只衰减将领封印 | 常规间隔 | 战前铺场，压力开始抬头。 |
| 苏醒 | 生成并激活 | 常规间隔 | 将领先压场，像前锋试探。 |
| 降临 | 维持当前存活数量 | 按生成间隔持续出波 | 决战阶段，真正的魔王战开始。 |
| 战后重建 | 清空 | 关闭 | 战后结算，世界喘口气。 |

## 玩家这一轮主要盯什么
- 预发展时，先看人口能不能稳定增长，因为它直接决定预兆什么时候触发。
- 进入预兆后，重点从“发展”转成“备战”，要开始看据点位置、军团节奏和将领封印。
- 将领苏醒后，玩家要观察王国是否扛得住前线压力，因为这通常是在魔王真正降临前的压力测试。
- 魔王降临后，玩家主要盯魔王态势、将领态势、军团态势和王国英雄的幸存情况。
- 打赢以后，重点又从“活下来”切回“留下什么”，也就是轮回进阶、英雄幸存强化和世界档位。

## 胜利、结算与重开
- 胜利条件固定是“击败本轮魔王”，不是清空所有军团，也不是摧毁据点。
- 多魔王时，只有最后一名存活魔王被击败，系统才会结算本轮。
- 结算顺序固定为：结算战果 -> 发放轮回进阶 -> 重置阶段与进度 -> 写入轮回历史 -> 开启下一轮。
- 轮回数在战后重建完成后按 `+1` 处理，所以“下一轮”是战后结算真正完成后才开始。

# 全局共用规则

## 术语与时间口径
| 术语 | 通俗解释 |
|---|---|
| 轮回 | 从一次“魔王被击败”到下一次“魔王被击败”的完整周期。 |
| 阶段 | 一轮轮回里固定顺序推进的分段，就像一场战役的不同章节。 |
| 将领封印 / 魔王封印 | 控制将领和魔王什么时候上场的两条进度条。 |
| 游戏时间单位（`world_time`） | WorldBox 自己在跑的时间刻度，不是现实世界的秒表。 |
| 游戏年 | 用 `world_time` 换算出来的年单位，`1年 = 60 world_time`。 |
| 王国 | 游戏里的 Kingdom 实体，拥有城市、人口和外交关系。 |

- 本文里写“秒”，默认都指游戏里的 `world_time`，不是现实钟表秒。
- 换算固定为：`1个月 = 5 world_time`，`1年 = 60 world_time`，`12个月 = 1年`。
- 游戏加速时，`world_time` 会长得更快，所以“持续 10 秒”看起来会更快结束。
- 游戏暂停时，`world_time` 不增长，所以按秒和按年的计时都会一起停住。

## 敌我、触发与效果口径
- 先判定目标是不是 `Actor` 生物单位；城市和建筑不走 Actor 特质与战斗技能流程。
- “友军”默认看同王国关系；“敌军”默认看敌对关系。条目里写 `castXXX` 只表示把效果投放出去，不等于已经完成敌我筛选。
- 文档里的“主动时”“命中时”“受击时”“死亡时”“常驻/周期时”都沿用游戏原版的触发入口；主文档只讲口径，不展开底层函数名。
- 未写概率默认按 `100%` 处理；未写低血阈值默认按 `30%`；“短眩晕 / 短混乱 / 短减速”默认沿用原版时长。
- “回填”表示受击后按比例回一部分血；“当前生命伤害”默认最低保留 `1HP`，只有明确写成处决类效果时才允许破这个底线。
- 视觉表现只服务玩家看得懂结果。只有真的会被玩家看到的投射物、范围区、召唤物和地形变化，才需要额外做表现层。

## 魔王阵营共用边界
- 魔王阵营单位固定只有三类：魔王、将领、军团。
- 这三类单位统一走 `wild kingdom` 口径，只拿它做阵营归属和敌我判定，不让它变成新文明。
- 魔王阵营不建王国、不建城、不走城市发展链，也不参与正常王国外交。
- 三类单位都必须使用独立图片资源，不能直接复用原版图片糊过去。
- 模板选型优先从 `wild/mob` 方向的母版起步，不把 `human`、`elf`、`orc`、`dwarf` 这类文明种族当通用底座。
- 据点是魔王阵营的出生和集结锚点。每个当轮魔王都会有自己的据点，详细生成与落地规则见 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 存档与资料边界
- 轮回状态、阶段、计时器、双封印进度、发放结果和关键随机结果都要写进 MOD 存档。
- 读档时要恢复“系统正在跑到哪一步”，而不只是恢复单位表面状态。
- 现在的资料分成两类：一类是名册、字段、条目、参数这类权威主表；另一类是锻造、签数这类专题说明。
- 以后补充文档时，先判断你要改的是“权威主表”还是“专题说明”，不要把同一份信息抄到多个地方一起维护。

# 系统总览

## 轮回系统
- 这块负责什么：它负责阶段推进、双封印管理、胜利结算和下一轮重置，像整套 MOD 的总进度条。
- 什么时候触发 / 结束：新档或上一轮战后重建完成后进入预发展；人口达标进预兆；将领封印归零进苏醒；魔王封印归零进降临；最后一名存活魔王被击败后进入战后重建。
- 玩家能看到什么、能调什么：HUD 和轮回窗口会显示轮回数、当前阶段、双封印和世界档位；可调项集中在预兆触发、预发展检查间隔和双封印衰减。
- 详细条目去哪里看：参数看 [系统参数总表](ERRE附属文档/系统参数总表.md) 的“轮回系统”；落地流程和存档边界看 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 魔王系统
- 这块负责什么：它负责魔王实体、多魔王互动、据点配套和魔王战斗行为，是整轮战役的核心敌方压力源。
- 什么时候触发 / 结束：预兆阶段先确定本轮魔王名单并生成据点；真正的魔王实体要等魔王封印归零后才降临；本轮战后重建时清空状态。
- 玩家能看到什么、能调什么：玩家会看到本轮有哪些魔王、是否多魔王、他们是联盟还是内战；可调项集中在魔王池、苏醒数量和多魔王互动参数。想指定魔王时，通过启用 / 关闭魔王池收窄候选范围。
- 详细条目去哪里看：技能条目看 [魔王名册与技能表](ERRE附属文档/魔王名册与技能表.md)，参数看 [系统参数总表](ERRE附属文档/系统参数总表.md)，实现边界看 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 将领系统
- 这块负责什么：将领是魔王阵营的精英单位，作用像魔王真正降临前的前锋和支柱。
- 什么时候触发 / 结束：将领只在苏醒阶段生成一次；每个魔王固定 `5` 名将领；将领死亡后不补员；战后重建时整轮清空。
- 玩家能看到什么、能调什么：玩家主要通过图鉴、单位详情和运行态看到将领名单与当前幸存情况；将领本身没有独立参数面板，节奏主要由轮回系统的封印推进控制。
- 详细条目去哪里看：名单看 [将领名册](ERRE附属文档/将领名册.md)，共享阵营规则和生成边界看 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 军团系统
- 这块负责什么：军团负责持续出波，让魔王阵营不是只靠几个 Boss 压场，而是一直有前线压力。
- 什么时候触发 / 结束：预兆阶段出第一波，之后按间隔持续出波；预发展和战后重建不出波；军团数量会随波次递增，但会受同时上限约束。
- 玩家能看到什么、能调什么：玩家主要看军团态势、当前出波节奏和同时上限；可调项集中在生成间隔、初始数量、同时上限和波次数量递增。
- 详细条目去哪里看：参数看 [系统参数总表](ERRE附属文档/系统参数总表.md) 的“军团系统”，实现边界看 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 轮回进阶系统
- 这块负责什么：它负责把“上一轮打赢了什么”转成“下一轮世界能拿到什么”，核心是装备解锁和特质解锁两条长期成长链。
- 什么时候触发 / 结束：每次轮回结算时统一发放；结果跨轮回生效，并跟着世界档位和王国档位一起往后走。
- 玩家能看到什么、能调什么：玩家会看到世界档位、王国档位模式、已解锁条目、静态说明和实例属性；可调项集中在档位推进、王国档位模式、魔王装备刷新和随机属性候选池。
- 详细条目去哪里看：条目和档位解锁看 [轮回阶位详表](ERRE附属文档/轮回阶位详表.md)，锻造口径、扣材字段映射和 `equipment_value` 换装判定看 [轮回装备锻造对比表](ERRE附属文档/轮回装备锻造对比表.md)，参数看 [系统参数总表](ERRE附属文档/系统参数总表.md)，实现细节看 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 公共特质系统
- 这块负责什么：它负责把新增公共特质接进原版特质体系，让这些特质能像原版特质一样被抽到、被展示、被手动授予。
- 什么时候触发 / 结束：条目在加载期注册；实际获得时机仍沿用原版出生、遗传、成长、突变箱和编辑器入口。
- 玩家能看到什么、能调什么：玩家主要在原版特质详情、原版特质编辑器和单位详情里看到它们；当前没有单独的公共特质模块，也没有独立参数面板。
- 详细条目去哪里看：条目和默认授予配置看 [公共特质表](ERRE附属文档/公共特质表.md)，字段名看 [属性字段速查](ERRE附属文档/属性字段速查.md)，出生 / 遗传 / 成长三池签数、原版默认补签和当前池子占比看 [特质签数对比表](ERRE附属文档/特质签数对比表.md)，实现口径看 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 等级系统
- 这块负责什么：它复用原版升级逻辑，只额外补一层“升级后随机属性加成”，让单位成长更有长期积累感。
- 什么时候触发 / 结束：所有 Actor 生物单位升级时都会结算；一次经验结算如果连续升多级，就按升级次数逐次发放。
- 玩家能看到什么、能调什么：玩家会在单位详情里看到“等级加成”页签，里面显示当前等级和累计加成总览；可调项集中在候选池、每级随机属性数和各属性单次加成值。
- 详细条目去哪里看：参数看 [系统参数总表](ERRE附属文档/系统参数总表.md) 的“等级系统”，实现口径看 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 王国系统
- 这块负责什么：它把王国声望做成长线成长，让王国不是只靠人口和军队变强，还会累积长期名望收益。
- 什么时候触发 / 结束：王国总声望达到对应阈值就立刻升级；达到等级上限后不再升，但总声望仍继续累积。
- 玩家能看到什么、能调什么：玩家会在王国详情里看到“声望加成”页签，里面显示当前声望等级、总声望和累计加成；可调项集中在等级上限、声望分段阈值、候选池和各属性单次加成值。
- 详细条目去哪里看：参数看 [系统参数总表](ERRE附属文档/系统参数总表.md) 的“王国系统”，实现口径看 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 英雄系统
- 这块负责什么：它负责命定英雄的晋升、家族继承、觉醒评分加成和跨轮幸存强化，是王国侧最明显的“人物成长线”。
- 什么时候触发 / 结束：繁荣和危机会触发英雄晋升；新生儿出生时会判定家族继承；轮回结算时会检查幸存英雄并发放幸存强化。
- 玩家能看到什么、能调什么：玩家会看到英雄名字后的标记、英雄幸存情况、血脉与觉醒结果；可调项集中在英雄上限、繁荣/危机阈值、候选评分、幸存强化和家族继承参数。
- 详细条目去哪里看：参数看 [系统参数总表](ERRE附属文档/系统参数总表.md) 的“英雄系统”，实现流程和状态存储看 [EraWheel_实现口径](EraWheel_实现口径.md)。

## 故事生成器
- 这块负责什么：它把真实发生过的事件整理成更有情绪和叙事感的故事，但不凭空造人物、地点、时间和因果。
- 什么时候触发 / 结束：系统持续增量收集事件，按年份分章后生成故事；它不直接参与战斗，只负责把轮回经历讲出来。
- 玩家能看到什么、能调什么：玩家会在故事窗口看到故事生成边界、LLM 连接配置和生成故事结果；当前主文档只定义素材边界和写作约束，不展开新的数值参数表。
- 详细条目去哪里看：运行流程和素材边界看 [EraWheel_实现口径](EraWheel_实现口径.md)；如果以后补故事参数，再统一进 [系统参数总表](ERRE附属文档/系统参数总表.md)。

# 数值成长总规则

## 随机写入时机
| 对象 | 什么时候写随机值 | 这一笔会不会重抽 | 读的时候怎么理解 |
|---|---|---|---|
| 魔王 | 生成时 | 不会 | 这一名魔王本轮出生时定好基础随机值。 |
| 将领 | 生成时 | 不会 | 将领也是生成那一刻定好，之后读档保持不变。 |
| 军团 | 每波生成时 | 本波不重抽；下一波可不同 | 同一波军团共用该波结果。 |
| 命定英雄 | 晋升时 | 不会 | 英雄的额外随机值只在晋升那一刻写一次。 |

## 同轮回稳定性
- 同一轮回内，随机范围固定不变，不会因为中途又刷出一个单位就把整轮范围改掉。
- 同类单位在同一轮回里使用同一套范围口径，所以“这一轮的魔王强度味道”会比较统一。
- 本轮新增单位不会触发范围平移，范围平移只在轮回结算时统一处理。

## 叠加顺序与范围平移
- 叠加顺序固定是：先写随机基础值，再叠特质和轮回进阶奖励。
- 范围平移只在轮回结算时执行一次，按本轮生成单位的均值更新下一轮下限，再用“下限 + 初始宽度”重算上限。
- 如果本轮没有生成对应单位，就不执行这类单位的范围平移。
- 玩家手动改了随机范围后，系统要清零原来的平移偏移，避免新手改完参数还被旧偏移偷偷影响。

## 详细数值去哪里看
- 具体的随机范围、默认值和区间输入方式，统一放到 [系统参数总表](ERRE附属文档/系统参数总表.md) 的“数值成长”章节。
- 这些随机值怎么写进单位、什么时候落盘、哪些地方不能重抽，统一放到 [EraWheel_实现口径](EraWheel_实现口径.md)。

# 界面总览

## 玩家看到的导航地图
| 层级 | 玩家看到什么 | 这层主要干什么 |
|---|---|---|
| `1` | `EraWheel` 顶层页签 | 进入 MOD 主入口。 |
| `2` | 模块按钮区 | 选择要看的系统。 |
| `3` | 系统窗口 | 查看介绍、调参、资料页和必要的运行态。 |
| `4` | 内容切换标签 | 在当前系统里切不同内容页。 |
| `HUD` | 战斗信息条 | 随时抬头看这一轮跑到哪了。 |

## 模块入口
- 模块按钮固定为：`导览`、`轮回系统`、`魔王系统`、`将领系统`、`军团系统`、`轮回进阶系统`、`等级系统`、`王国系统`、`英雄系统`、`故事生成器`。
- `导览` 负责 `导览` 和 `设置` 两个内容页，不替其它系统代管图鉴和参数。
- 各系统不再强制套用统一数量的内容页；只保留当前确实需要的 `介绍`、`参数调整`、`图鉴 / 图谱`、`运行态` 等标签。
- `故事生成器` 使用 `介绍 / 参数调整 / 生成故事`，连接配置放在参数页，生成结果放在生成故事页。

## HUD 看什么
- HUD 常驻显示：轮回数、当前阶段、世界档位、将领封印、魔王封印、魔王态势、将领态势、军团态势、王国英雄。
- 它只负责战斗中快速看状态，不负责替代系统窗口做详细调参。
- HUD 可以拖拽移动；显示开关和位置记忆都归 `导览 -> 设置`。
- HUD 现在固定为结构化战况面板，不再提供“标准 / 紧凑”样式切换。

## 导入导出从哪进
- 导入导出入口统一放在 `导览 -> 设置`，不额外再开一个独立按钮。
- 导出对象只包含玩法参数，不包含运行态存档，也不包含敏感集成字段。
- 导入时先检查 `config_version`，版本不一致先迁移，再给玩家看差异预览，最后才允许应用。
- 应用前要先自动备份；应用失败要能回滚并给出原因。

## 想改界面或实现时去哪里看
- 想查窗口怎么复用、参数控件用什么、图鉴和运行态怎么分层，去看 [EraWheel_实现口径](EraWheel_实现口径.md)。
- 想查某个控件背后到底改的是哪个参数，去看 [系统参数总表](ERRE附属文档/系统参数总表.md)。
