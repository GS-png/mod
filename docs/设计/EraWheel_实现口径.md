# EraWheel 实现口径

## 文档定位
- 这份文档是给后续实现、查链路和排障的人看的，不是给第一次看玩法的人看的。
- 主玩法说明看 [EraWheel_Redesign.md](EraWheel_Redesign.md)，所有可调参数看 [系统参数总表.md](ERRE附属文档/系统参数总表.md)。
- 这里集中记录三类东西：运行时判定口径、界面复用方式、资产与 API 接入边界。

## 共用运行口径

### 时间口径
- 文档里出现的“秒”统一指游戏时间单位 `world_time`，不是现实钟表秒。
- 换算固定为：`1个月 = 5 world_time`，`1年 = 60 world_time`，`12个月 = 1年`。
- 游戏加速会让 `world_time` 更快增长，所以同一个“持续 10 秒”在高倍速下会更快结束。
- 游戏暂停时 `world_time` 不增长，所以按秒和按年的计时都会暂停。

### 敌我判定
- 先判定目标是否为 Actor 单位。
- 城市和建筑不参与 Actor 特质流程。
- 轮回阶位先按类型分流，再按对象应用。
- “友军”默认用 `Actor.isSameKingdom(target)` 判定。
- “敌军”默认用 `self.areFoes(target)` 判定，底层是 `kingdom.isEnemy(target.kingdom)`。
- 技能枚举目标前先判目标存活且存在王国，再做敌我筛选。
- 条目里写 `castXXX` 只表示投放动作，不代表已完成敌我筛选。

### 原版技能、法术触发口径
- `主动时 x%` 使用战斗施法链：`Actor.tryToAttack -> addToAttackPool(combat_cast_spell) -> CombatActionLibrary.tryToCastSpell`。
- `命中时 x%` 使用命中回调链：`MapBox.applyAttack -> Actor.attackTargetActions`。
- `受击时 x%` 使用受击回调链：`Actor.getHit -> s_get_hit_action / action_get_hit`。
- `死亡时 x%` 使用死亡回调链：`Actor.checkCallbacksOnDeath -> action_death`。
- `常驻 / 周期时 x%` 使用特质轮询链：`Actor.checkActionsFromAllMetas -> action_special_effect`，触发间隔由 `special_effect_interval` 控制。
- `action_on_object_remove` 只表示对象移除回调，不默认等同 `action_death`。
- “累计触发 / 条件触发 / 战斗光环”只表示条件，不新增触发入口。

### 技能、法术效果默认值
- 未写概率视为 `100%`。
- 低血未写阈值时默认按 `30%` 处理。
- “短眩晕 / 短混乱 / 短减速”统一使用原版默认时长。
- “回填”表示受击后恢复本次伤害的一定比例。
- “当前生命伤害”默认最低保留 `1HP`，处决类技能可例外。
- 技能、法术实现口径只允许三类：`原版直接复用`、`原版修改复用 + MOD 自定义`、`MOD 自定义`。
- 游戏原版技能、法术和特质对照看 [游戏原版特质与效果清单.md](ERRE附属文档/游戏原版特质与效果清单.md)。

### 数值字段
- 字段命名统一使用 [属性字段速查.md](ERRE附属文档/属性字段速查.md)。
- 先按字段效果确认用途，再按配置填写方式写值。
- `multiplier_` 前缀字段统一按百分比口径处理。

## 系统实现细则

### 轮回系统
- 定义：轮回系统负责阶段推进、双封印管理和结算发放；战后重建结束后，轮回数按 `+1` 处理。
- 判定规则：阶段推进由轮回系统统一驱动；阶段阈值只读取人口、将领封印 / 魔王封印进度和 HP；胜利结算只由击杀魔王触发；多魔王时最后一名存活魔王被击败后触发结算。
- 系统执行流程：
  1. 按检查间隔读取人口，判定是否从预发展进入预兆。
  2. 进入预兆后确定本轮魔王名单，并初始化据点和军团节奏。
  3. 管理双封印衰减，将领封印清零后生成将领，魔王封印清零后生成魔王。
  4. 命中胜利条件后执行结算，发放进阶奖励，写轮回历史并回到预发展。
- 存档边界：轮回状态、阶段、计时器和进度都写入 MOD 存档；读档后必须恢复阶段、将领封印 / 魔王封印进度和剩余间隔；轮回系统只管理推进与结算，不接管战斗子状态。
- 参数入口：看 [系统参数总表.md](ERRE附属文档/系统参数总表.md) 的“轮回系统”。

### 魔王阵营通用规则
- 单位组成：魔王阵营单位包含魔王、将领、军团。三类单位统一以原版单位母版模板克隆，再分别改成魔王、将领、军团专用模板；默认不从 `human`、`elf`、`orc`、`dwarf` 这类具体文明种族模板起步。
- 阵营归属：统一使用 `wild kingdom` 建模，只做阵营归属和敌我判定；模板必须配置 `kingdom_id_wild`，并保持 `kingdom_id_civilization` 为空；模板选型必须落在 `wild / mob` 向母版链，禁止挂入文明链。
- 索敌口径：魔王、将领、军团默认攻击所有非己方阵营生物单位；索敌目标不以王国归属作为前置条件。
- 共享边界：魔王阵营不建王国、城镇和新文明，不调用 `buildCityAndStartCivilization`；不创建 City，不进入入城和城市发展链路；不参与王国外交关系。

### 据点系统
- 定义：据点系统负责魔王阵营据点的生成、维护和失效。每个当轮苏醒魔王对应一个据点。
- 代码口径：已批准美术底座统一收口为 `7x3` footprint，代码口径统一为 `BuildingFundament(3,3,2,0)`。
- 生成规则：预兆阶段确定魔王名单后生成据点，每轮回地点随机；选点必须可行走陆地，且避开深水与拥挤地块；生成失败时按“附近可行走地块”回退重试。
- 运行规则：魔王、将领、军团优先在对应据点生成；魔王与将领的据点绑定关系写入存档并在读档恢复。
- 退出规则：战后重建阶段清理本轮据点状态；下一轮由新的名单重新生成。

### 魔王系统
- 定义：魔王系统只负责魔王实体、技能行为和多魔王互动；阵营归属、模板和索敌等共享规则只看“魔王阵营通用规则”。
- 条目归属：每个魔王的技能条目都维护在 [魔王名册与技能表.md](ERRE附属文档/魔王名册与技能表.md)。
- 多魔王互动：触发条件为本轮苏醒数 `>= 2` 或当前存活数 `>= 2`；互动模式支持联盟、内战、随机；随机模式按关系校验间隔重掷关系；联盟模式强制停火并共享敌对目标；内战模式互相宣战，同时继续攻击王国；内战胜者获得称号和限时属性加成；联盟或内战只改外交关系，不改技能敌我口径。
- 参数入口：看 [系统参数总表.md](ERRE附属文档/系统参数总表.md) 的“魔王系统”。

### 将领系统
- 定义：将领是魔王阵营精英单位，承担指挥和关键战斗。
- 固定规则：每个魔王固定配置 `5` 名将领；将领只在苏醒阶段生成一次；将领死亡后不补充。
- 条目归属：将领名单只在 [将领名册.md](ERRE附属文档/将领名册.md) 维护；数量、生成阶段、补员规则和生成位置看本节固定规则。
- 参数入口：看 [系统参数总表.md](ERRE附属文档/系统参数总表.md) 的“将领系统”。将领生成基础范围归属将领系统参数页；将领封印仍归轮回系统；将领名单仍归将领名册。

### 军团系统
- 定义：军团是魔王阵营波次单位，用于持续施压。
- 波次规则：预发展和战后重建阶段不出波；预兆阶段生成第一波，后续按生成间隔生成下一波；波次数量按“数量递增”随波次提高。
- 上限处理：本波数量按 `min(计划数量, 同时上限 - 当前存活)` 计算；计算结果 `<= 0` 时跳过本波并记录日志。
- 参数入口：看 [系统参数总表.md](ERRE附属文档/系统参数总表.md) 的“军团系统”。

### 轮回进阶系统
- 定义：轮回结算后，系统统一发放进阶奖励；进阶奖励跨轮回生效，只包含装备解锁和特质解锁两条链路；档位结果、随机结果和发放日志都写入存档，读档后保持一致。
- 条目归属：具体条目和数值由 [轮回阶位详表.md](ERRE附属文档/轮回阶位详表.md) 维护。
- 专题入口：如果要看 `crafting.material_id` 到原版扣材字段的映射、当前轮回装备实际走哪些原版锻造字段、`equipment_value` 在原版换装判定里的作用，去看 [轮回装备锻造对比表.md](ERRE附属文档/轮回装备锻造对比表.md)。
- 进阶类型：`装备解锁` 作用于王国成员和魔王势力；`特质解锁` 作用于王国成员和魔王势力，走原版随机池。
- 档位计算：
  - 当前世界档位统一截断到 `1-轮回阶位上限`。
  - `自动推进`：`min(轮回阶位上限, 上轮世界档位 + 每轮回档位提升)`。
  - `手动控制`：当前世界档位固定读取手动世界档位。
  - 魔王势力装备档位和特质档位固定等于当前世界档位。
  - 王国档位模式是单选参数：`全部世界档位`、`全部王国档位`、`幸存王国世界档位 + 新王国王国档位`。
  - 王国档位基值公式：`max(新王国档位下限, floor(当前世界档位 × 掌控度))`。
  - 掌控度公式：`基础分 + Σ(指标分 × 权重)`，结果统一截断到 `0%-100%`。
  - 指标分公式：`min(当前值/阈值, 1)`；指标包含书籍、城市、人口、军力。
  - 需要王国档位基值时，如果王国统计缺失，系统只用基础分和档位下限，不阻断结算。
- 发放流程：
  - 统一前置：先算当前世界档位，再按王国档位模式算每个王国的生效档位，最后按“装备解锁 -> 特质解锁”顺序发放。
  - 王国装备链路：把装备条目注册进装备编辑器；条目解锁后进入原版装备候选池；原版锻造前按王国生效档位过滤轮回装备条目；原版锻造生成装备实例后进入城市仓库；单位按原版取装逻辑获取装备。
  - 魔王装备直发与换装链路：按当前世界档位过滤轮回装备条目，再并入统一已解锁候选池；保留原版出生带装入口，不阻断 `default_weapons / ownerless_item`；魔王、将领生成时必得六槽位；军团生成时按每槽位 `0.2` 概率发放；目标槽位非空时，按 `Item.getValue()` 只替换更高值装备；每隔 `N` 年刷新六槽位，军团有空槽位继续走概率发放。
  - 特质链路：编辑器保持全局可见，未解锁条目保持锁定；王国成员按王国生效档位过滤，魔王势力按当前世界档位过滤；未达标条目跳过并重抽；互斥和概率、获取由原版逻辑处理；发放结果写入日志和存档。
- 随机属性：装备实例和特质实例共用同一套随机属性规则；发放时默认抽取 `N` 个属性，单次不重复；每个命中属性按独立 `min~max` 区间结算；随机结果写入存档和日志，读档后不重抽；随机结果只对具体实例生效。
- 展示规则：
  - 轮回特质和轮回装备继续复用游戏原版的特质详情、装备详情、特质编辑器和装备编辑器入口，不单独做第二套编辑器。
  - 静态展示统一按“效果说明 + 随机范围说明”展示；这里主要对应特质详情和装备编辑器里的未绑定条目；不显示实例属性加成面板。
  - 装备实例悬浮提示继续保留原版来源说明；装备说明区继续显示轮回效果说明；属性区继续走原版 `stats / durability / kills` 结构，但绿色最终属性值要直接并入实例属性结果，不再额外展开第二块实例属性区。
  - 装备详情大面板继续保留原版来源说明、原版按钮和原版属性区；轮回装备的大面板与 hover tooltip 保持同一口径，只显示一组原版最终属性行，不再插入 `当前实例属性加成` 标题或第二组属性行。
  - 当前轮回共享随机池包含少量原版默认 `hidden=true` 的 stat；启动阶段会统一把 `area_of_effect`、`multiplier_mass` 解隐藏，并给 `multiplier_mass` 补主属性显示名，保证“随机 6 条”在复用原版属性区时可见。
  - 轮回特质实例提示继续按现有口径显示；`当前实例属性加成` 只在存在具体实例上下文时显示；没有绑定实例时不显示空白属性区块。
- 实现边界：
  - 魔王链路只允许 `generateItem / generateModsFor / ActorEquipment.setItem`。
  - 魔王链路换装判定统一使用 `Item.getValue()`，不引入自定义评分体系。
  - 特质过滤只在原版随机池授予时执行。
  - 手动授予不做档位过滤。
  - 禁止用全局 `ItemAsset.unlock()` 代替资格判定。
- 参数入口：看 [系统参数总表.md](ERRE附属文档/系统参数总表.md) 的“轮回进阶系统”。

### 公共特质系统
- 定义：公共特质系统负责读取、校验、注册 [公共特质表.md](ERRE附属文档/公共特质表.md) 的条目；该系统只扩展特质数量，不新增获得入口，不改原版授予逻辑。
- 专题入口：如果要看公共特质和轮回特质在 `出生 / 遗传 / 成长` 三个池子里的签数分布、原版默认补签与 MOD 显式遗传签的差异、当前池子占比是否失衡，去看 [特质签数对比表.md](ERRE附属文档/特质签数对比表.md)。
- 条目规则：
  - `trait_id` 必须全局唯一，重复 `trait_id` 只保留首条，后续重复条目跳过并记日志。
  - `属性加成（基础值）` 按“全局规则 -> 数值字段”映射写入对应字段。
  - `效果说明` 必须写清楚该特质实际做什么，供特质详情直接展示。
  - `属性加成（基础值）` 只写固定基础属性；条件触发、概率触发、地形触发、死亡触发这类机制效果继续写在效果说明中。
- 展示规则：公共特质详情复用原版特质详情逻辑；卡片统一按“效果说明 + 属性加成”展示；有基础属性加成时必须列出对应属性；没有基础属性加成时不强制显示空属性区块。
- 获得与生效：主要用于拓展注册游戏原版的特质数量，其它逻辑沿用原版随机池、原版事件和编辑器手动授予；使用 `ActorTrait` 注册，只作用于 Actor 单位；数值属性继续走原版 `ActorTrait / base_stats` 生效链路。

### 等级系统
- 定义：等级系统复用游戏原版生物单位等级逻辑，不改原版经验来源、升级阈值和等级显示；MOD 只新增“升级后随机属性加成”，不替换原版 `addExperience()` 和升级判定。
- 作用范围：系统作用于所有 Actor 生物单位，不作用于城市和建筑。
- 展示规则：在生物详情窗口中新增“等级加成”内容页入口，入口与原版装备、族谱、心智等内容入口并列；页面只显示当前等级与全部属性当前总加成，不展示逐级账本和单次随机命中明细；当前值为 `0` 的属性也显示。
- 升级加成规则：等级加成按“单位当前等级”累计；等级为 `1` 时就应已有 `1` 级对应的加成账本；每次结算从当前候选池随机抽取 `N` 个属性，单次不重复；一次经验结算如果连续提升多级，系统按“升了几级就结算几次”执行，不合并；加成结果写入存档和日志，读档后不重抽、不回滚。
- 参数入口：看 [系统参数总表.md](ERRE附属文档/系统参数总表.md) 的“等级系统”。

### 王国系统
- 定义：王国系统负责各王国维度的长期成长与声望等级。
- 展示规则：在王国详情窗口中新增“声望加成”内容页入口；页面只显示当前声望等级、当前总声望与全部属性当前总加成，不展示逐级账本和单次随机命中明细；当前值为 `0` 的属性也显示。
- 王国声望等级：
  - 主进度直接复用原版 `Kingdom.renown`。
  - 声望使用累计总值口径，只增不减用于升级判定，不消耗、不清零。
  - 系统按王国当前总声望和阈值分段，实时映射当前声望等级。
  - 等级效果作用于所属王国的 Actor 单位。
  - 达到等级上限后不再升级，后续新增声望只继续累计到总声望里。
- 等级效果：王国声望等级每提升 `1` 级，系统立即发放 `1` 次随机属性加成；每次加成默认随机属性，单次抽取不重复；属性命中后按该属性的独立加成参数叠加。
- 参数入口：看 [系统参数总表.md](ERRE附属文档/系统参数总表.md) 的“王国系统”。

### 英雄系统
- 定义：英雄系统负责命定英雄的生成、强化、家族继承和幸存强化；EraWheel 复用原版 `Family`、父母 ID 和族谱链做英雄祖先追溯，不额外新造一套家族系统。
- 名称标记：命定英雄晋升后会获得 `1` 个名称标记追加在名字后；名称标记写入后保持稳定，读档不重抽；名称标记池固定为 `30` 个条目，不做全局唯一限制。
- 命定晋升：
  - 触发来源包括繁荣触发和危机触发。
  - 晋升流程：先检查世界总英雄上限，再检查王国英雄上限，再判定王国累计人口增长是否达到 `200` 的整数倍门槛，或命中危机阈值；通过后进入候选筛选与评分；从综合分前 `N` 名里随机 `1` 名执行晋升强化；若本次累计晋升次数大于 `1`，重复执行直到次数用完或命中上限。
  - 候选评分：候选池只包含同王国、存活、非魔王阵营单位；评分指标为等级、击杀、生命、攻击、指挥；公式为 `综合分 = Σ(min(指标/阈值,1) × 权重)`；只有已觉醒并成功继承先祖属性的候选，才按觉醒评分加成修正综合分。
  - 晋升强化：晋升时按“数值成长 -> 随机范围 -> 英雄”写入基础值，只写一次；已有装备槽位不清空；空槽位补齐，非空槽位按 `Item.getValue()` 只替换更高值；晋升强化写入后立刻落盘，读档不重抽、不重算。
- 家族继承：
  - 触发时机固定为王国新生单位出生时，入口固定为 `all_actions_actor_birth`。
  - 原版复用基础：沿用 `parent_id_1`、`parent_id_2`、`Family` 和家谱 / 族谱链路做亲缘基础。
  - 追溯规则：沿双亲亲缘链向上追溯最近的英雄祖先；双亲都命中时按代数最近优先；超过可继承代数时终止；祖先存活与否不影响判定。
  - 继承结算：命中英雄祖先后按概率判定继承；成功时按“祖先晋升基础值 × 继承比例”写入继承属性，并将后裔视为已觉醒；失败时只保留血脉链路，不进入觉醒状态。
- 状态存储：血脉根 ID 写入 `custom_data_long`；血脉代数写入 `custom_data_int`；状态随单位存档与读档恢复。
- 幸存强化：轮回结算时检查命定英雄是否存活；存活到结算的命定英雄获得幸存强化基础属性；每轮只发放一次；本轮死亡英雄不获得本轮强化；强化达到上限后不再继续叠加。
- 参数入口：看 [系统参数总表.md](ERRE附属文档/系统参数总表.md) 的“英雄系统”。

### 故事生成器
- 定义：故事生成器只使用真实发生的内容作为素材，不新增人物、地点、时间和因果；LLM 只负责把素材改写成更有情感张力的故事。
- 数据来源：游戏原版世界历史；“智域与生命”中的已收藏生物、已收藏物品、计划与阴谋、战争、军队、联盟、王国、村镇、氏族、宗教、文化、语言、家庭、亚种等逻辑内容；MOD 自定义事件。
- 生成流程：
  1. 系统增量采集并记录 `last_year`。
  2. 系统标准化事件结构。
  3. 事件年份大于单位 `death_year` 时丢弃。
  4. 事件按年份排序并分章。
  5. 系统生成故事小说写入故事 UI。
- LLM 约束：输入只允许结构化事件与规则；无法追溯来源的句子直接丢弃。

### 数值成长运行规则
- 随机规则：属性随机基础值只在单位生成或晋升时随机写入一次；魔王和将领在生成时随机一次；军团每波随机一次，并共享该波结果；命定英雄在晋升时随机一次。
- 轮回口径：同一轮回内随机范围固定不变；同类单位在本轮使用同一随机范围；本轮新增单位不会触发范围平移。
- 叠加顺序：`随机值 -> 特质 / 进阶奖励`。
- 范围平移：只在轮回结算时执行一次；平移按本轮生成单位均值更新下轮下限；上限按“下限 + 初始宽度”重算；本轮无生成数据时不执行平移；玩家手动改动随机范围后，系统清零平移偏移。
- 远程 projectile 口径：EraWheel 魔王阵营远程 projectile 出手点会自动按当前 `scale` 修正；当 `scale` 过小时，发射口径按人类模板基准下限收口，不额外暴露“发射偏移”类参数。

## 界面复用与导航实现

### 复用原则
- 本本章固定使用 5 个界面术语：`EraWheel 顶层页签`、`EraWheel 模块按钮区`、`EraWheel 系统窗口`、`EraWheel 窗口切换栏`、`EraWheel 内容切换标签`。
- EraWheel 只新增自己的入口内容、窗口内容和参数绑定；页签切换、按钮开窗、窗口切换、分页切换都继续复用游戏原版逻辑。
- `WindowToolbar` 是窗口切换栏，负责切不同系统窗口；`WindowMetaTab` 是内容切换标签，负责切同一窗口内的内容页。
- EraWheel 系统窗口中，窗口切换栏统一放左侧，内容切换标签统一放顶部；详情窗口沿用各自原版布局。
- HUD 只保留战斗中必须抬头确认的信息，不承担模块导航和参数编辑职责。

### 原版复用映射
| 层级 | EraWheel 结构 | 原版复用对象 | 用途 |
|---|---|---|---|
| `1` | `EraWheel 顶层页签` | `PowerTabAsset / PowersTab` | 把 EraWheel 挂到原版顶层页签栏。 |
| `2` | `EraWheel 模块按钮区` | `PowerButton.open_window_id -> ScrollWindow.showWindow(...)` | 在页签内展示模块按钮，点击后进入对应窗口。 |
| `3a` | `EraWheel 窗口切换栏` | `WindowToolbar` | 在同一组系统窗口之间切换。 |
| `3b` | `EraWheel 内容切换标签` | `WindowMetaTabButtonsContainer / WindowMetaTab` | 在当前系统窗口内切换内容页。 |

### 导航与窗口分组结构
- 顶层只提供一个 `EraWheel` 页签。
- 进入页签后，原版返回、暂停、时间倍率等控制按钮保持原版前排顺序；EraWheel 的 `导览`、`轮回系统`、`魔王系统`、`将领系统`、`军团系统`、`轮回进阶系统`、`等级系统`、`王国系统`、`英雄系统`、`故事生成器` 10 个模块入口统一追加在后面。
- 点击模块按钮后，进入对应的 `EraWheel 系统窗口`。
- 当前系统若属于同一主题组，则通过窗口切换栏切换同组系统窗口。
- 进入具体系统窗口后，再通过内容切换标签切换该系统的不同内容页。
  - 组 `1`：`导览`、`轮回系统`、`魔王系统`、`将领系统`、`军团系统`。
  - 组 `2`：`轮回进阶系统`、`等级系统`、`王国系统`、`英雄系统`、`故事生成器`。

### 系统窗口职责
- `导览`：介绍 MOD 定位，并提供导览层设置。
- `轮回系统`：介绍阶段推进、双封印、胜利结算，并提供轮回主线参数。
- `魔王系统`：介绍魔王定义、多魔王互动和魔王战斗逻辑，并提供本系统参数。
- `将领系统`：介绍将领作用、生成方式和战场职责，并提供本系统参数。
- `军团系统`：介绍军团波次、压制节奏和阶段变化，并提供本系统参数。
- `轮回进阶系统`：介绍轮回奖励、世界档位、长期成长和解锁逻辑，并提供本系统参数。
- `等级系统`：介绍升级成长、随机属性和成长结果，并提供本系统参数。
- `王国系统`：介绍王国声望、王国成长和王国侧强化，并提供本系统参数。
- `英雄系统`：介绍命定英雄、家族继承、幸存强化和血脉逻辑，并提供本系统参数。
- `故事生成器`：介绍故事生成边界，提供 LLM 连接配置，并展示生成故事结果。

### 内容切换标签
- EraWheel 方案中，系统窗口里的内容切换标签统一放在窗口顶部，图标悬停显示标签名称。
- 内容切换标签不套用统一数量，而是按当前系统实际需要保留必要标签。
- `导览` 使用 2 个顶部标签：`导览`、`设置`。
- `轮回系统` 使用 2 个顶部标签：`介绍`、`参数调整`。
- `魔王系统`、`将领系统`、`军团系统` 使用 4 个顶部标签：`介绍`、`参数调整`、`图鉴`、`运行态`。
- `轮回进阶系统` 使用 3 个顶部标签：`介绍`、`参数调整`、`图谱`。
- `等级系统`、`王国系统`、`英雄系统` 使用 2 个顶部标签：`介绍`、`参数调整`。
- `故事生成器` 使用 3 个顶部标签：`介绍`、`参数调整`、`生成故事`。
- `介绍` 只讲这个系统是什么、为什么存在、玩家应重点看什么。
- `参数调整` 只展示该系统参数表里的可调项；同一参数页内如有多个分组，再用页内分组按钮切换。
- `图鉴 / 图谱` 只展示本系统直接相关的资料项，不承担配置写入。
- `运行态` 只给确实需要实时摘要的系统保留；没有明确运行态价值的系统不保留占位页。
- `生成故事` 只展示故事生成结果；连接配置放在 `参数调整`。

### 参数交互规则
- `普通数值参数` 使用可编辑数值框。
- `启用 / 关闭参数` 使用状态切换按钮，不使用文字下拉，也不使用 `0/1` 输入框。
- `带启用状态的数值参数` 使用“数值框 + 启用状态框”的行式布局。
- `枚举型参数` 一律使用折叠下拉框。
- `区间型参数` 一律使用 `最小值 ~ 最大值` 的成对输入形式。
- `阈值区间参数` 使用 `最小值 ~ 最大值 + 每级 / 每段消耗` 的组合形式。
- `评分类参数` 使用“阈值 + 权重”的组合形式。
- `导览设置` 这类独立开关可以使用勾选框。

### UI 文字排版与空白断开规范
- 新建或修改 EraWheel 系统窗口时，文字层级、字间距、行距和内容断开空白必须复用本节规范。
- `letterSpacing` 默认不写；如果工具必须显式写入，统一写 `0`。
- 不允许为了单页效果临时压缩字距、放大字距或改负字距。

| 文字分类 | 节点示例 | 字号 | 字重 | 行距 | 段落规则 |
|---|---|---:|---:|---|---|
| 窗口主标题 | `Guide Window Title` | `28` | `700` | 默认 | 单行。 |
| 分区 / 分类标题 | `Guide What Title`、`Guide Flow Title`、`Settings HUD Title` | `28` | `700` | 默认 | 单行。 |
| 普通正文 | `Guide What Body`、`Guide Flow Body`、`hudNotes` | `20` | `500` | `1.22` | 段内用 `\n`，不使用空行。 |
| 技能弹窗长正文 | `copyTruncated`、`fullReferenceBody` | `20` | `600` | `1.18` | 技能段之间使用 `\n\n`。 |
| 控件项目名 / 列表主文本 | `paramLabel`、`choiceName`、`demonCodexRowText` | `20` | `600` | 默认 | 单行。 |
| 主要按钮 / 控件值 | `paramValueText`、`demonCodexButtonText`、`exportLabel` | `18` | `700` | 默认 | 单行。 |
| 辅助说明 / 卡片描述 | `paramDesc`、`demonCodexDesc` | `16` | `500` | `1.12` | 不使用空行。 |
| 次级操作按钮 | `selectorButtonText` | `16` | `700` | 默认 | 单行。 |
| 符号 / 图标文字 | `choiceCheckboxTick`、`hudTick`、`dropdownArrow` | `18` / `16` | `700` | 默认 | 单行。 |
| 画布说明标签 | `Runtime Label`、`Reference Label` | `20` | `700` | 默认 | 只用于设计稿标注。 |

- 普通正文只用单换行分隔句组，避免一页松、一页紧。
- 技能弹窗长正文内容较长，可以用更紧的 `1.18` 行距；每个技能块之间保留一个空行。
- 标题、按钮、标签和图标文字不设置 `lineHeight`；垂直居中交给文本框高度和 `textAlignVertical`。
- 内容区块之间不再放置横向分割线。
- 上方正文或内容块底部到下方标题顶部固定为 `56px`，直接用大段空白表示内容断开。
- 弹窗标题底部到正文顶部保持约 `40px` 空白，避免正文挤压按钮。
- 控件内部结构线不属于内容分割线；例如下拉控件内部竖线可以保留。

### 内容归属规则
- 各系统玩法说明以对应系统章节为准，并落到对应系统窗口的 `介绍` 标签。
- 各系统可调参数以 [系统参数总表.md](ERRE附属文档/系统参数总表.md) 为准，并落到对应系统窗口的 `参数调整` 标签。
- 各系统资料内容落到对应系统窗口的 `图鉴 / 图谱` 标签，不再单独设置总资料入口。
- `导览` 只负责总览和设置，不承接具体系统图鉴和具体系统参数。
- `故事生成器` 只承接介绍、LLM 连接配置和生成故事结果，不混入普通玩法参数。
- 魔王、将领、轮回阶位、公共特质和原版对照条目仍以附属文档为准。

### HUD、收藏、导入导出
- HUD 常驻显示：轮回数、当前阶段、世界档位、将领封印、魔王封印、魔王态势、将领态势、军团态势、王国英雄。
- HUD 支持鼠标拖拽移动；显示开关和位置记忆归 `导览 -> 设置`。
- HUD 固定使用结构化战况面板实现，不再保留样式切换或文本框双轨。
- 收藏开关字段固定为 `can_be_favorited`；魔王、将领、命定英雄在生成或晋升时自动收藏。
- 导入导出入口并入 `导览 -> 设置`；导出对象只包含 MOD 玩法参数；导入时先解析并检查 `config_version`；版本不一致时先迁移，再展示差异预览；用户确认后才应用；应用前自动创建备份；应用失败时回滚备份并提示原因。

## 资产生成链路

### 单位生成链路
- 单位扩展：用 `ActorAsset` 定义单位模板，再注册到 `AssetManager.actor_library`。单位属性、外观、默认特质、默认装备等由 `ActorAsset` 定义。
- 单位生成：统一使用 `ActorManager.spawnNewUnit(ActorAssetID, WorldTile, ...)`；实例初始化继续走游戏原版 `createNewUnit(...) / spawnNewUnit(...)` 链路。
- 生成链路口径：原版负责单位实例创建、默认装备生成、特质初始化、王国归属等流程；MOD 只扩展模板与生成参数，不重写底层生成逻辑。
- 模板规范：优先从原版单位母版模板起步，再克隆成独立模板，最后覆盖需要的属性、外观和资源；只有当目标单位本质上就是某个具体种族的变体时，才从 `human`、`elf`、`orc`、`dwarf` 这类具体种族模板起步。
- 模板与实例要分开写：这里的“克隆”指 `ActorAsset` 模板克隆，不是复制地图上已存在的运行时单位实例。
- 标准顺序固定为：选择母版模板 -> 克隆独立 `ActorAsset` -> 覆盖需要的字段和资源 -> 注册到 `AssetManager.actor_library` -> 通过 `spawnNewUnit(...)` 生成实例。
- 魔王阵营远程 projectile 出手位置继续复用原版标准远程公式，只在 `ProjectileManager.spawn(...)` 前对过小 `scale` 套一层人类模板基准下限，不改 `size`、攻击距离、AoE 或命中半径。

| 母版 ID | 定位 | 自带内容 | 实现风险 | 推荐用途 | 不推荐用途 |
|---|---|---|---|---|---|
| `$civ_unit$` | 文明单位基础母版 | 已进入文明链；带 `civ`、家庭结构、灵魂、人形体型、手部攻击、亚种链、常见生物转化链。 | 容易天然继承文明链语义。 | 新文明种、会进入文明系统的人形单位。 | 一次性召唤物、军团兵、纯 wild 怪物。 |
| `$civ_advanced_unit$` | 更完整的人形文明母版 | 在 `$civ_unit$` 基础上补齐人形皮肤组，`is_humanoid` 明确为真。 | 更接近四大文明种，借壳做人形怪物时容易带入文明居民口径。 | 新人形种族、具体文明变体。 | 魔王军团、野怪、构装召唤物。 |
| `$mob_no_genes$` | 最干净的 wild / mob 母版 | 无文明归属、无建造模板、默认 `base_attack`、不走亚种链。 | 很多生物链能力要手动补。 | 召唤物、军团、魔王 / 将领、一次性战斗单位。 | 需要完整生育、亚种、感染扩散的活体生物。 |
| `$mob$` | 带生物链的 wild / mob 母版 | 默认 `base_attack`，可有亚种，可走丧尸 / 蘑菇 / 肿瘤等生物转化链。 | 容易无意带入亚种、感染、转化副作用。 | 需要保留部分活体特征的怪物、野生生物型敌军。 | 只负责战斗表现的召唤分身、一次性镜像。 |
| `$animal_base$` | 动物总底座 | 默认动物口径、关闭高级贴图，保留常规动物基础能力。 | 直接拿来做终态容易欠缺行为约束。 | 需要自己继续细化行为的动物底。 | 直接当成最终动物模板长期使用。 |
| `$animal$` | 标准攻击型动物母版 | 默认 `jaws` 攻击，能掉肉，保留动物侧生物转化链。 | 会更像“会咬人的动物”。 | 野兽、魔兽、普通攻击型动物。 | 温顺动物、观赏动物。 |
| `$peaceful_animal$` | 温顺动物母版 | 基于动物链，自带 `peaceful`，伤害更低。 | 如果目标其实需要主动战斗，行为倾向会偏温顺。 | 鹿、羊、兔、观赏生物。 | 狼、狮、怪兽、战斗宠物。 |
| `$carnivore$` | 肉食动物母版 | 基于 `$animal$`，补了 `diet_carnivore`。 | 会沿用攻击型动物口径。 | 狼、虎、鳄鱼、掠食型魔兽。 | 草食兽、温顺坐骑。 |
| `$herbivore$` | 草食动物母版 | 基于动物链，补了 `diet_herbivore`，保留常规动物能力。 | 默认不是进攻向模板。 | 牛、羊、鹿、食草兽。 | 掠食动物、战斗怪。 |
| `$omnivore$` | 杂食动物母版 | 基于 `$animal$`，补了 `diet_omnivore`。 | 会保留一部分攻击型动物倾向。 | 熊、猪、杂食怪物。 | 纯温顺动物、虫类。 |
| `$insect$` | 小型虫类母版 | 小体型、低生命、低伤害、无婴儿形态、默认 `peaceful`、虫类侧归属。 | 太小太脆，天然带“虫子”口径。 | 甲虫、虫群单位、小型虫怪。 | 人形、巨兽、军团主战单位。 |
| `$flying_insect$` | 飞行虫类母版 | 基于 `$insect$`，补 `weightless` 和悬浮 / 飞行语义。 | 仍然是虫类模板。 | 蜜蜂、蝴蝶、飞虫、空中虫群。 | 天使、恶魔、飞龙、飞行召唤兽。 |

- 模板选型规则：
  - 文明人形单位优先从 `$civ_unit$` 或 `$civ_advanced_unit$` 起步；只有当目标明确是“具体文明种族变体”时，才从对应具体种族模板起步。
  - 召唤物、军团、魔物优先从 `$mob_no_genes$` 或 `$mob$` 起步；是否需要生物链副作用，由“要不要亚种 / 感染 / 转化”决定。
  - 动物单位优先从 `$animal_base$`、`$animal$`、`$peaceful_animal$`、`$carnivore$`、`$herbivore$`、`$omnivore$` 中选离目标最近的那层。
  - 虫类单位优先从 `$insect$` 或 `$flying_insect$` 起步；如果目标只是“会飞”，但本体不是虫，不要误用虫类母版。
  - 默认选离目标最近、同时副作用最少的母版；不确定时，优先选更干净的母版，再手动补能力。
- 实现红线：
  - 禁止把 `human`、`elf`、`orc`、`dwarf` 这类具体种族当通用母版。
  - 禁止没有明确需求时直接继承文明链字段，如 `kingdom_id_civilization`、`architecture_id`、`build_order_template_id`、文化 / 宗教 / 语言 trait。
  - 禁止文档只写“克隆原版单位”而不说明克隆来源层级。
  - 禁止把运行时实例复制链路写成模板注册方案。
- 常见错误示例：
  - 直接从 `human` 克隆召唤物，容易把文明归属、建筑风格、家族链和具体文明配置一起带进去。
  - 本来只需要一次性战斗单位，却从 `$mob$` 起步，容易无意带入亚种、感染、转化副作用。
  - 本来要做会主动战斗的野兽，却从 `$peaceful_animal$` 起步，后续还得反向把和平倾向拆掉。

### 装备生成链路
- 装备扩展：用 `EquipmentAsset`（继承 `ItemAsset`）定义装备，再注册到 `AssetManager.items`。装备属性和固定效果直接由 `EquipmentAsset` 定义，生成 / 锻造 / 发放链路走游戏原版逻辑。
- 装备词条扩展：用 `ItemModAsset` 定义词条，再注册到 `AssetManager.items_modifiers`。词条附加属性和附加效果由 `ItemModAsset` 定义，挂载和随机生成链路走游戏原版逻辑。
- 装备分组扩展：用 `ItemGroupAsset` 定义分组，再注册到 `AssetManager.item_groups`。分组展示和分类走游戏原版逻辑。

### 特质生成链路
- 特质扩展：使用 `ActorTrait` 定义特质，并注册到 `AssetManager.traits`。特质的属性、数值效果和行为回调由 `ActorTrait` 本体定义。
- 授予方式：特质授予方式沿用游戏原版 `ActorTrait` 入口，但需按路径分别接入。出生、遗传、成长、突变箱、训练主要由 `ActorTrait` 字段控制；`biome`、事件、固定出生和手动赋予由外部配置或调用决定。
- 原版真实遗传口径是 `rate_birth + rate_inherit`。原版还存在一条默认补签：当 `rate_inherit == 0` 时，会自动补成 `rate_birth * 10`。
- 当前 MOD 不走这条原版默认补签。公共特质和轮回特质都显式把 manifest 里的 `inherit_weight` 写入运行时 `rate_inherit`。
- 如果要核对三类特质在出生池、遗传字段、实际遗传和成长池里的签数分布，以及当前配置有没有把池子挤偏，去看 [特质签数对比表.md](ERRE附属文档/特质签数对比表.md)。

### 建筑生成链路
- 建筑扩展：用 `BuildingAsset` 定义建筑，再注册到 `AssetManager.buildings`。放置 / 建造链路走游戏原版逻辑。
- 据点是当前最主要的建筑扩展场景；正式落地时优先把 footprint、占地判定和回退逻辑统一封在据点注册与放置链路里，不把这些约束散落到战斗系统里。
