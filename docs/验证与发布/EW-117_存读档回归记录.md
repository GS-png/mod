# EW-117 存读档回归记录

## 记录目的
- 这份记录对应 `EW-117`。
- 它要验证三件事：阶段中读档、战斗中读档、结算前后读档。
- 核心口径只有一句话：关键状态不能丢，也不能重复结算。

## 当前证据
- `Observed`：运行态存档会把阶段、轮回数、世界档位、双封印、军团波次、多魔王关系、王国成长、英雄档案和轮回历史一起写进 `EraWorldRuntimeState`。
- `Observed`：运行态会在世界绑定时尝试读档，在状态变化或按月持久化时回写 `RuntimeEnvelope`。
- `Observed`：读档只接受当前运行态版本。旧 EraWheel 运行态存档不再迁移，测试时默认新开世界。
- `Observed`：读档归一化只负责补齐当前版本运行态里的缺失列表和计时器，避免新测试档因为空字段直接断链。
- `Unknown`：仓库里没有真实 `WorldBox` 运行环境，所以这份文档现在先给出回归脚本，还没有实机结果。

## 回归前准备
1. 先按 [EW-114_启动自检清单.md](EW-114_启动自检清单.md) 确认启动校验通过。
2. 再按 [EW-116_多魔王全量轮回手工脚本.md](EW-116_多魔王全量轮回手工脚本.md) 把轮回推进到多魔王场景。
3. 全程打开 `EraWheel -> 轮回系统 -> 运行态` 和 HUD。这样像看仪表盘，读档前后更容易比对。

## 阶段中读档
1. 在 `预兆` 阶段存一次档。记录当前阶段、将领封印、轮回数，以及本轮魔王候选摘要。
2. 退出到主菜单后立刻读档。确认阶段仍是 `预兆`，将领封印继续从原进度往下走，不会重置回 `100%`。
3. 再把流程推进到 `苏醒` 阶段重复一次。确认魔王封印、据点绑定和已生成将领不会因为读档重复刷一遍。
4. 如果这里已经出现“阶段倒退”“据点重建两次”“将领重复生成”，就直接记为阻塞。

## 战斗中读档
1. 把流程推进到 `降临`。确保本轮至少有 `2` 名魔王，且已经出过至少 `1` 波军团。
2. 存档前记录 4 项：当前阶段、军团态势、多魔王关系说明、HUD 上的轮回数。
3. 读档后先不要做别的操作，只看运行态和 HUD。期望它们和读档前一致。
4. 再继续观察一个 `关系校验间隔`。如果是 `随机` 模式，要确认关系仍按间隔重掷，而不是因为读档提前重掷或永远不再重掷。

## 结算前后读档
1. 在最后一名存活魔王即将死亡前存一次档。记录当前轮回数、世界档位，以及是否已经进入战后重建。
2. 读档后完成击杀。确认只触发一次胜利结算，轮回数不会跳两次，轮回进阶不会发两次。
3. 进入 `战后重建` 后再存一次档。读档后确认阶段仍是 `战后重建`，不会退回 `降临`。
4. 等到重建真正完成。确认轮回数只在重建结束后 `+1`，并且下一轮回到 `预发展`。

## 关键检查点
- 阶段不能倒退。
- 双封印进度不能重置。
- 多魔王关系说明不能消失。
- 已出波军团不能因为读档整轮重刷。
- 胜利结算、轮回进阶、历史记录都只能记一次。

## 通过标准
- 三类读档都能恢复到正确阶段。
- 运行态、HUD 和事件口径能对上，不出现“画面显示一套，内部跑另一套”。
- 结算后不会重复加轮回数，不会重复发成长奖励，也不会丢失上一轮历史。

## 当前边界
- `Observed`：代码层已经有运行态版本号、`mod_id` 校验和当前版本空字段归一化。
- `Observed`：旧 EraWheel 世界运行态迁移已移除，旧版本 `RuntimeEnvelope` 会被拒绝读取。
- `Unknown`：真实实机里“战斗中特效很多时读档”的稳定性，还需要进游戏回填结果。
