## Game Vision

### Core Concept

《世纪轮回•魔王》是 WorldBox 的轮回对抗 MOD，核心体验是魔王周期入侵世界、文明联合反抗，并在封印胜利与世界毁灭之间持续轮回。

### Elevator Pitch

《世纪轮回•魔王》是一个基于 WorldBox 原玩法的轮回入侵对抗 MOD，不改原版核心玩法。
玩家依然按原版方式发展和观察世界，但世界会周期遭遇魔王、将领和军团入侵，进入跨王国对抗与封印战。
世界会在“封印成功后的新一轮轮回”与“被魔王毁灭”之间持续拉扯，带来更强的可玩性和压迫感。

### Vision Statement

我们希望玩家每一轮都像在追一部自己亲手推动的文明史诗，看到王国在灾难中的兴衰、反击与传承。
这个 MOD 在不改变 WorldBox 原生玩法的前提下，增加明确的长期目标、危机压力和轮回成长，提升整体可玩性。
我们希望它最终被玩家评价为：好玩、刺激、有代入感，而且值得反复开新档体验。

## Target Market

### Primary Audience

主受众是 16-40 岁、已经熟悉 WorldBox 的休闲到核心玩家。
他们愿意长期观察文明演化，也接受中高强度危机事件和多轮回成长系统。

**Demographics:**
16-40 岁；以熟悉或老玩家为主；游玩时段覆盖碎片时间与周末/晚间长局。

**Gaming Preferences:**
偏好不改原版基础玩法的扩展内容；接受参数调节、长线养成、战局波动和反复开档测试。

**Motivations:**
追求爽感、策略深度和文明叙事感，想在“魔王入侵 vs 世界反抗”的循环里获得持续新鲜感。

### Secondary Audience

次受众包含三类：
1. 只玩原版沙盒、还没接触高压对抗线的玩家。
2. 喜欢看文明演化剧情、但不追求极限操作的玩家。
3. 喜欢反复开新档、测试参数和流派组合的实验型玩家。

### Market Context

当前主要定位是社区驱动的兴趣项目，不以商业竞争为首要目标。
核心机会点是“魔王入侵 + 世界轮回”这条持续危机主线，为原版沙盒提供明确长期目标和阶段压迫感。
项目启动时机来自作者个人长期游玩需求，先服务已有体验痛点，再逐步扩展玩法深度。

**Similar Successful Games:**
暂未设定明确对标作品；当前以 WorldBox 原版体验为基础参照。

**Market Opportunity:**
以 QQ 群和玩家社群分发为起点，采用“玩家直接获取代码并放入 MODS 加载”的方式快速触达核心用户，先做小范围口碑验证再扩散。

## Game Fundamentals

### Core Gameplay Pillars

1. 原版不改：不推翻 WorldBox 原玩法，只做扩展增强。
2. 轮回危机：魔王周期入侵，世界必须持续对抗。
3. 长线成长：每轮有积累、有变化，不是打一波就结束。
4. 史诗叙事：让玩家看到文明兴衰，像追一部长篇小说。

**Pillar Priority:** When pillars conflict, prioritize:
轮回危机 > 原版不改 > 长线成长 > 史诗叙事

### Primary Mechanics

1. 观察与决策：持续查看世界阶段、封印进度和战局变化，并据此调整参数和策略。
2. 轮回推进：从预发展到封印战再到重建，围绕阶段目标推进整轮流程。
3. 阵营对抗：王国与魔王阵营持续交战，围绕据点、军团、遗迹进行拉扯。
4. 英雄与王国成长：通过抗魔等级、命定英雄、家族继承形成长期战力差。
5. 进阶构筑：通过轮回阶位（装备、特质、军事增幅）进行跨轮回构筑。

**Core Loop:** 观察世界状态 -> 识别当前阶段风险 -> 调整配置与战局策略 -> 对抗魔王阵营并推进封印战 -> 结算轮回并获得进阶成长 -> 进入下一轮更高压对抗。

### Player Experience Goals

1. 危机压迫与反转快感：魔王入侵带来持续压力，关键节点反击和翻盘带来强烈释放感。
2. 策略掌控感：玩家通过阶段判断、参数配置和调度行为，能明显改变战局走向。
3. 文明史诗代入感：玩家像在追一部自己推动的文明史诗，看到王国兴衰与传承。
4. 长线成长满足感：轮回间持续积累，玩家能明确感知“下一轮更强、更稳”。

**Emotional Journey:** 开局观察与准备（预期）-> 魔王入侵升级（紧张）-> 多线对抗与决策（专注）-> 封印战冲刺（高压）-> 胜负结算与成长（释放/成就）-> 新轮回重开（期待）。

## Scope and Constraints

### Target Platforms

**Primary:** PC (WorldBox + NeoModLoader)
**Secondary:** 无

### Budget Considerations

项目采用自费模式开发。
当前没有明确的外包或采购预算，优先使用自研实现和现有资源。
范围上明确不做多人功能，不做新音频资源，以控制复杂度和维护成本。

### Team Resources

当前团队为 1 人兼职开发。
角色覆盖策划、开发、测试三个核心职能，需求沟通链路短，迭代决策快。

**Skill Gaps:** 暂无明确技能缺口；如后续出现专项瓶颈，再按问题补充外部支持。

### Technical Constraints

1. 技术栈固定为 WorldBox 0.51.2+、NeoModLoader、C#，不迁移引擎。
2. 性能上避免全图高频扫描，军团与轮回推进采用低频调度。
3. 功能边界不包含多人联机和外部服务器依赖。
4. 资源边界不新增音频资源，优先复用原版可验证链路。
5. 兼容目标以单机本地 MOD 稳定加载运行为第一优先级。

### Scope Realities

该项目是单人兼职、社区分发导向的 WorldBox MOD，核心目标是稳定实现“魔王入侵 + 世界轮回”主线体验。
因此功能优先级会向可维护、可验证、可稳定落地倾斜，而不是追求一次性覆盖所有扩展想法。
后续范围扩展应以“是否服务核心支柱、是否增加不成比例维护成本”作为准入标准。

## Reference Framework

### Inspiration Games

**WorldBox 原版**

- Taking: 沙盒演化观察体验、原版系统逻辑和内容复用方式。
- Not Taking: 缺少长期危机主线和明确阶段终局压力的体验。

**玄幻世界小说母题（非具体游戏）**

- Taking: 反派入侵、世界纪元轮回、文明兴衰与反击的叙事框架。
- Not Taking: 纯线性主角推进和固定剧本结局。

### Competitive Analysis

**Direct Competitors:**
WorldBox 原版、其他 WorldBox 功能型 MOD。

**Competitor Strengths:**
其他 MOD 往往能自然融入原版逻辑，复用原版内容成熟，上手成本低。

**Competitor Weaknesses:**
普遍缺少“魔王入侵 + 世界轮回 + 明确阶段闭环”的完整高压玩法主线。

### Key Differentiators

1. 六阶段轮回闭环：从预发展到封印战再到重建的完整循环，不是单点功能补丁。
2. 双封印与多系统联动：将领封印与魔王封印驱动将领、军团、遗迹、外交同步变化。
3. 跨轮回成长体系：轮回阶位、王国抗魔、命定英雄继承构成长线可积累体验。
4. 原版兼容导向：不改原版核心玩法，通过原版链路扩展出持续危机线。

**Unique Value Proposition:**
《世纪轮回•魔王》在不破坏 WorldBox 原生玩法的前提下，提供一个可持续反复游玩的“魔王入侵-文明反抗-轮回成长”完整闭环体验。

## Content Framework

### World and Setting

游戏发生在 WorldBox 的奇幻文明世界中，多王国并存，并周期遭遇魔王入侵。
世界观深度定位为中等：有纪元轮回规则和阵营设定，但不走超重设定文路线。
整体采用玩法与叙事并重的方向，用战局变化推动叙事体验。

### Narrative Approach

叙事方式以 Emergent（涌现叙事）为主，Environmental（环境叙事）为辅。
不采用线性主角剧情、过场动画和强制对白驱动。

**Story Delivery:** 通过世界历史日志、阶段事件、战争结果和轮回结算文本来呈现叙事。

### Content Volume

内容体量以“完整闭环优先”控制：先稳定实现轮回阶段、魔王阵营、封印战和跨轮回成长主线。
扩展内容按核心支柱分批加入，避免单人兼职下出现不可维护的内容膨胀。
优先保证可反复开档的系统深度，而不是一次性堆叠大量外围内容。

## Art and Audio Direction

### Visual Style

视觉风格延续 WorldBox 像素风和原版可读性，重点强化魔王阵营辨识度与状态反馈。
常态阶段保持自然文明色调，入侵与封印战阶段提高对比和警示感。
动画复杂度控制在中低档，优先信息清晰和战局可读，不追求高成本演出。

**References:** WorldBox 原版视觉风格与 UI 信息表达方式。

### Audio Style

音频策略以复用原版为主，不新增语音和音乐资源。
通过事件节奏和视觉反馈补足紧张感与阶段压迫感。

### Production Approach

生产方式以代码驱动效果和现有资产复用为核心，不依赖大规模外包。
在单人兼职条件下，优先完成高价值主线系统并保证稳定性与可维护性。

## Risk Assessment

### Key Risks

1. 多系统联动导致状态错乱或性能抖动。
2. 单人兼职下功能范围持续膨胀。
3. 版本更新或其他 MOD 冲突引发兼容问题。
4. 系统复杂导致玩家上手门槛偏高。
5. 社区分发路径导致触达范围有限。

### Technical Challenges

核心挑战在于阶段状态机、封印进度、军团节奏、遗迹调度与存档恢复的一致性。
同时需要在不做高频全图扫描的前提下，保持战局反馈及时与稳定。

### Market Risks

项目以社区兴趣驱动为主，天然不走大规模商业发行路径。
主要风险是扩散速度慢、外部可见度低，需要依靠持续口碑积累。

### Mitigation Strategies

1. 用统一状态机与低频调度控制系统复杂度，关键状态全量落盘并做读档校验。
2. 以核心支柱作为范围闸门，先保“轮回-封印-成长”闭环，非核心内容延后。
3. 固定目标版本分阶段适配，统一字段映射并增加冲突检测日志。
4. UI 采用“先结论后原因”，保留基础模式与默认预设降低上手门槛。
5. 先在 QQ 群做小规模验证，沉淀演示档和配置包后再逐步扩散。
